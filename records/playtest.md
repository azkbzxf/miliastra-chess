### 本轮修掉的真实缺陷（均为模拟器实测发现，沙箱与 perft 都测不出）

**F-1 棋子图元溢出到相邻格（已修）**
`create_image` 建管控件时 `pivot=(0,0)`（左下角），但图元渲染按「中心锚点」算位置，
导致每枚棋子的图元整体右上偏移半个宽高、互相重叠加串格。
修复：`SetAnchoredPosition` 时减去半个宽高，让中心点落到正确位置。

**F-2 点击完全没有反应（已修，根因两条）**
1. `ENABLE_RAYCAST_FIELD=false` 时跳过写 `raycastTarget`，而未写该字段的光标检测区**收不到任何事件**。
   探针对照：直接实例化并写 `raycastTarget=true` 的光标区能触发回调；走 `create_cursor_area`（被开关跳过）的完全无反应。
   修复：`ENABLE_RAYCAST_FIELD=true`，且赋值一律包 `pcall`——未实现该字段的环境会抛错被吞掉，不阻断启动。
2. 棋盘 64 个命中区是在 `build_board` 内先建的，之后建的棋子图元/面板/弹窗是同级后出现的节点，
   在上层把命中区盖住。修复：`build_all_ui` 末尾对 64 个命中区统一 `SetAsLastSibling()` 提到最顶层。

**F-3 光标检测区 visible 未显式置真（已修）**
`create_cursor_area` 只 `SetActive(false)`，补 `SetVisible(true)`。

**F-4 面板按钮全部点不动（已修）**
面板按钮命中区（新开/认输/求和/同屏/样式）在 `build_panel` 里建，
被其后创建的结算/升变/确认弹窗盖住，层级与 F-2 第 2 条同源。
修复：`build_all_ui` 末尾把面板命中区与棋盘 64 个一并提到最顶层。
回归：样式按钮点两次，按钮文字正确轮转（该按钮后续已在 v1.3 删除，见下）。

### 坐标备忘（后续自动化用）

模拟器 `pointer` 的 x/y 是**画布坐标、原点左下、Y 向上**（与 Lua 布局坐标同一套），
不是屏幕坐标。1600×900 下格宽 87.75、棋盘左下 (449, 99)：
```
格号 sq -> 像素: x = 449 + (sq % 8) * 87.75 + 43.9
                 y =  99 + (sq // 8) * 87.75 + 43.9
例：e2 = sq 12 -> (800, 230)；e4 = sq 28 -> (800, 406)
```
面板按钮（1600×900，同样左下原点）：新开(1337, 322)、认输(1513, 322)、求和(1337, 233)、
同屏(1513, 233)；结算「再来一局」中心 (800, 341)；确认框「确定」左键中心 (638, 379)、
「取消/拒绝」右键中心 (962, 379)。

### 本轮修掉的真实缺陷（均为模拟器实测发现）

**D-01 认输方判定看「轮到谁」而不是「谁点的按钮」（已修）**
现象：黑方回合时白方点认输，结算显示「**黑方**点了认输」。
根因：`hitYes` 里用 `GAME.st.turn` 判断认输方。同屏模式下两者等价，但联机模式下
我可以在对方回合点认输，此时 `st.turn` 是对方。
修复：联机模式用 `GAME.mySide`，同屏模式才用当前轮次。

**D-02 结算面板标题行不显示（已修）**
现象：认输结算只看到说明行「白方点了认输」，标题「白方认输，黑方胜」一片空白。
根因：文本框可用高度 = 控件高 − 上下内边距（≈0.45×字号），行高 = 字号×1.2。
标题字号 44 → 行高 52.8 + 内边距 19.8 = 需要 72.6，而控件高只有 `0.18×360=64.8`，
装不下 → 整行被吞。
修复：标题高度 `0.18 → 0.26`（86.4 > 72.6），y 由 0.62 → 0.60 保持整体居中。
> 这是一类**只在模拟器/真机才暴露**的缺陷：沙箱只记 API 调用，不看文本是否能排进控件框。

**D-03 联机求和三条文案/回声缺陷（已修）**
1. 接收方弹窗文案错：`show_confirm()` 没传 kind，`kind=nil` 走 `CONFIRM_SPEC.newgame`
   兜底 → 对方收到求和却弹「重开会清空这一局」，按钮是「确定/取消」。
   修复：改 `show_confirm("draw")`。
2. 发起方自己弹出「对方想和棋」：服务端节点图是「收到即广播给房间内所有人」，
   **包括发送者自己**。修复：`GAME.drawReqSent` 标记吃掉自己的回声。
3. 和棋结算标题取 `RESULT_DRAW_AGREED_AGREED`（多打了一个 `_AGREED`，该键不存在）→
   标题 nil 空白；且 `EV_DRAW_ACC` 分支同样取错键 + 重复 `show_result()`。
   修复：统一用 `RESULT_DRAW_AGREED`，并按逼和/五十步/三次重复/子力不足分档标题。

**D-05 自己走子的回声被当成对方走子（已修）**
现象：单人试玩走 e2→e4 后日志出现 `[Chess] error 收到无法验证的走子信号：12→28`。
根因：服务端广播把我自己的走子也发回给我；本地已 `apply_move`，起点格已空，
再按「对方走子」重算必然找不到合法走法 → 误报错误。棋盘本身没错（走子只生效一次），
但日志污染 + 在双人时会造成一次多余的校验失败。
修复：`GAME.lastSentMove` 记下刚发出的 `{from,to,promo}`，收到时精确匹配三项即丢弃回声。
> 这是「回声」问题的第 3 类：走子。D-03 是求和/同意。凡是要广播的信号都要过这一遍。

**D-04 服务端容器里残留示例控件（已修）**
模拟器新建工程自带的「文本框 / 图片(五角星)」等示例控件会盖在棋盘上。
修复：删掉示例控件，容器节点下只留 7 个不会被 Lua 用到的空占位节点。

### 本轮修的缺陷（全部 runtime=simulator）

**D-06 每枚棋子带一圈白方块 / 光晕大圆（已修）**
现象：首版每枚棋子外面都有方形底色块，还有覆盖整幅画面的半透明大圆。
根因两条：
1. 拟合把「棋子 + 白底纸」整幅一起拟合，`ELEMENTS` 里混了还原白底纸的块；
   直接全画出来就等于给每枚棋子垫一张白纸。
2. `PW`/`KW`/`NW` 三份 `BACKGROUND_COUNT=0`，第一条就是 `alpha 47~74`、覆盖全图的半透明椭圆
   （原图羽化光晕），被当成棋子本体画了出来。
修复：只用暗色元素（`luma <= 90`）算棋子包围盒；暗色块中心落框内保留，
浅色块要求整个外接框在框内且 `alpha >= 180`；`alpha < 100` 与覆盖面积 > 50% 的块直接丢弃。

**D-07 色块散开成「爆炸」状（已修）**
现象：首版棋子不是完整轮廓，而是一堆斜置色块四散飞出格子。
根因：槽位图元用 `pivot=(0,0)`，而 `SetLocalRotation` 是**绕 pivot 旋转**的；
用左下角做轴心，任何斜置的色块都会被甩到很远。
修复：`create_image` 增加 `pivot` 选项，棋子图元统一 `pivot=0.5`；
`paint_slot` 相应改为直接传中心坐标（不再减半个宽高）。

**D-08 黑兵下方灰色椭圆 / 整枚棋子被压扁（已修）**
现象：黑方棋子下方留一片灰色椭圆；PB 的棋子明显比其它压扁。
根因两条：
1. 暗色阈值取 150 时，底纸过渡用的**中灰块**也被判成「暗色」而无条件保留。
   收紧到 90（真正墨迹接近纯黑）。
2. 填充模式会输出**伸到画布外**的图元（拟合器把越界当免费得分）。
   PB 有越界块的归一化 y 变成 `-0.24`，参与包围盒后把棋子范围撑高 24%，整枚被压扁。
   修复：先按「旋转后外接框完全落在 0..1」筛一遍，再算包围盒。

> 这三条都是**只在模拟器画面里才看得见**的缺陷：数据本身合法、API 调用全成功、
> 沙箱也不会报错。必须靠截图逐轮核对。

### 本轮修掉的真实缺陷（全部 runtime=simulator）

**D-09 结算面板新增「复盘」按钮在开局就画在棋盘上（已修）**
现象：开局截图里「复盘」按钮直接盖在棋盘 e3 格上。
根因：给结算面板加了 `UI.result.btnReview` / `hitReview`，但 `hide_result()` 里只写了旧的

修复：`show_result` 与 `hide_result` 两处都补上 `btnReview` / `hitReview`。
> 教训：**往结算面板加控件，必须同时改 `show_result` 和 `hide_result`**。漏一处就是「弹窗控件常驻屏幕上」。

**D-10 退出复盘后轮次行残留「复盘 · 第 N/M 步」（已修）**
现象：结算后进复盘→退出，结算面板回来了，但面板轮次行仍写着「复盘 · 第 1/1 步」。
根因：`update_turn_text` 开头写 `if GAME.over then return end` —— 终局时它**直接返回不写文本**，
于是复盘期间写进去的进度行没人覆盖，就留在屏上了。
修复：终局分支改成写 `CONFIG.TEXT.TURN_OVER`（「棋局结束」，策划案 S-07 原本就要求这条文案）。
> 这是「不写」比「写错」更隐蔽的一类缺陷：代码没有报错、没有崩溃，只是少了一次 setter。

**D-11 `view_clocks` 未定义即调用，启动直接崩（已修）**
现象：首版 `start` 报 `mountError: OnStart: sim/levelScript.lua:1982: attempt to call a nil value (global 'view_clocks')`，
界面建完就中断，`mountError` 非空。
根因：我把复盘视图函数（`review_snap` / `view_board` / `view_state` / `view_clocks` / `view_captured` /
`review_turn_text`）插到了 `update_clock_text` **之后**。Lua 的 `local function` 是词法向前作用域，
渲染函数看不到后面才声明的 local → 运行期变成 nil 调用。
修复：把整块视图函数上移到 `format_clock` / `set_clock_labels` 之前（紧跟 GAME 表定义）。
`review_render` 因为被 `enter_review` 调用、自身又调用渲染函数，用「先 `local review_render` 前向声明、段末再赋值」处理。
> 这正是我在代码注释里写过的坑，结果自己踩了一次。**改完立刻试玩才发现**——静态检查（块结构平衡）发现不了这类错误。

### 与既有结论的差异（新增）

### 描边算法为什么是 per-shape pad（结论性判断，别再翻案）

两份文件的注释互相矛盾，必须给一个可判定的理由，而不是"感觉哪个好看"。

**判据是数学的，不是审美的：**

对单个形状，两种做法等价——各自外扩 t ≡ 绕中心放大到外缘外移 t。
**对并集则不等价。**

- **per-shape pad**：`∪(Sᵢ ⊕ t)`。Minkowski 和对并集**可分配**，
  所以这**恰好等于** `(∪Sᵢ) ⊕ t` —— 并集整体向外扩 t，**一圈边严格均匀**。
- **绕中心等比放大**：`∪(k·Sᵢ)`。由于各形状到中心距离不同，
  离中心远的形状被推出去更多，**远侧的边比近侧的边粗**。同一枚棋子上下/左右描边不等宽。

所以 sim 版（per-shape）是正确的，交付版（scale）会让棋子"发胖"。

**交付版注释里那条"反面做法"是怎么来的**：当时真正的台阶来源是
**拿一串宽度递减的矩形去逼近曲线**，不是外扩算法。改描边算法没能解决那个台阶
（因为根因不在这），于是被误记成了"per-shape pad 是错的"。后来形状改算法拟合、
矩形/椭圆/三角各尽其用，台阶问题自然就没了。

**约束**：`pad` 必须是「每个形状各自外扩 t，中心不动」，
`SetSizeDelta(w*sside + pad*2, h*sside + pad*2)` 且 `SetAnchoredPosition` 不带缩放项。
不要引入 `ek` / `rcx` / `rcy` 那套绕中心做法。

### 过程教训：多个 agent 并发写同一批文件

本轮中途有多路 agent 被派去改同一批文件（`sim/`、`lua/`、`docs/pieces-fit-*`），
互相覆盖，导致一度出现「两份 `piece_art_of` 定义」「半写坏的棋表」等中间态。

**结论**：形状拟合这类会重写整张表的任务，**不要并行派给多个 agent**，
或者必须给每个 agent 分配**不同的输出文件名**。写作用域重叠在文件系统层面不是锁。

### 本轮抓到的真 bug：终局音效永远不响（静默失败）

**发现方式**：不是跑出来的 —— 是 review 时把 10 个 `sfx_play(...)` 调用点**逐个对回
`CONFIG.SFX` 的键名**才发现的。模拟器根本捉不到它（它不报错、不写日志）。

```
L3540  sfx_play("over")   ← 表里的键叫 GAME_END，不叫 OVER
       → CONFIG.SFX["over"] = nil
       → string.upper → CONFIG.SFX["OVER"] = nil
       → return nil        ← 终局音效永远不播，且完全无声无息
```

根源是**两处命名不同步**：Demo 侧写 `SFX.play("over")`，Lua 侧的键名定成了 `GAME_END`，
实现时照着 Demo 抄了调用点，忘了键名已经改过。

1. 调用点 `sfx_play("over")` → `sfx_play("GAME_END")`，并加注释说明为什么不能写 `"over"`。
2. **把「键名写错」和「配置为 0」拆成两个分支**。原来是一句：
   ```lua
   if id == nil or id == 0 then return nil end   -- ← 把 bug 和合法配置合并，这是静默的根源
   ```
   现在 `id == nil` 会 `log_err("音效键名不存在：…")` 且每个键只报一次；`id == 0` 保持静默（合法关闭）。
   **只修调用点只能救这一次，修这一层才能救这一类。**

#### 4:3 截断 bug（本轮新发现，issue #1 第 3 条的延伸）

- **根因**：`fontScale` 只按 `canvasH/900` 缩放，但面板宽度是按 `canvasW` 比例算的。
  4:3 画布「更高但更窄」（960 高 / 1280 宽），于是字号 1.067 倍（变大）、
  面板宽 0.80 倍（变小），相对溢出 1.33 倍，文字被控件边框裁掉。
- **修法**：`fontScale = min(canvasW/1600, canvasH/900)`，取两方向较小者。
- **为什么安全**：四个已验档位的 min 值与原值**逐位相同**（都是宽高同比或宽度更紧），
  只有 4:3 从 1.067 修正为 0.800。Demo 侧同式同步修改，两份文件 SHA256 一致。
- **门禁**：新增 **CHECK-8**，断言 `fontScale` 表达式同时含 `canvasW`/`canvasH` 且用
  `math.min`，并把五档新旧值打进输出。
  这条 bug 在 1600×900 / 1280×720 上完全看不出来，靠人眼验会一直漏。

## 2026-11-05 · v1.12 issue #3 修复 + API 全面审计（runtime=simulator）

环境：千星 UI 模拟器，canvas `pc-16-9`（1600×900），Lua Runtime。
执行者：AI（`qxqy_studio_play` start/pointer/runCase/get{inspect:true}）。

### 一、issue #3 根因与修复

**症状**：选中一枚棋子后，盘面上同时出现「本次的绿点」与「上一次选中剩下的绿点」，
后者指向的格子这枚棋子走不到；点那些绿点无反应。

**根因**：`select_square` **不先清空落点池**。`UI.legalHL[1..28]` 是按索引复用的固定池，
旧代码只把本次用到的前 n 个 `SetActive(true)`，然后把 `UI.legalHLUsed = n`，
**从不关闭上一次打开的那些**。于是「先选 8 落点的子、再选 2 落点的子」就会残留 6 个绿点。

**为什么前几轮没抓到**：`clear_highlights()`（取消选中/走子/新开局/退出复盘）本身是对的，
它会把 28 个全关。bug 只在**「直接从一个子改选另一个子」**这条路径上出现。

**修法**：抽出 `hide_legal_pool()`，`clear_highlights()` 与 `select_square()` 共用，
`select_square` 在绘制新落点前调用。
