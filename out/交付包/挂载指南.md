## 6 步速查（全手工路径）

| # | 做什么 | 一句话 |
|---|---|---|
| **1** | 建**客户端控件容器** | 界面控件组管理 → 界面布局 → 添加界面控件 → 客户端控件容器 → 画布设置 → **前往编辑** |
| **2** | 建 **3 个控件模板** | 界面控件组库 → **客户端控件模板** → 添加客户端控件：**文本框**、**光标检测区域**、**图片**（各建一个，各保存一次） |
| **3** | 导入脚本 | 窗口 → **客户端脚本资源管理器** → 文件夹右键 → **新建脚本映射** → 编辑路径 → 选 `levelScript.lua` |
| **4** | 填 **4 个索引** | 记事本打开 `levelScript.lua`，把 CONFIG 里 4 个 `0` 换成你编辑器上看到的编号 |
| **5** | 挂脚本 | 容器画布 → 选中**容器节点** → 右侧【脚本】页签 → 添加脚本 → 选 `levelScript` |
| **6** | 保存 → 进关卡试玩 | 验收见 [导入方案.md · 第 8 节](导入方案.md#第-8-节验收清单) |

## 第 4 步要填的是这 4 行

```lua
CONTAINER_NODE_INDEX = 0,   -- ← 容器节点索引
PREFAB_TEXT_BOX      = 0,   -- ← 文本框模板索引
PREFAB_CURSOR_AREA   = 0,   -- ← 光标检测区域模板索引
PREFAB_IMAGE         = 0,   -- ← 图片控件模板索引
```

**三条铁律**（详细理由见 [第 5 节](导入方案.md#第-5-节4-个索引的读取与填写最容易错的一步)）：

1. 填的是**模板最外层**的索引，**不是**模板内部子控件的索引
2. 四个都**必填**，任何一个留 `0` 就报「界面零件还没配好」并停机
3. **以你编辑器上显示的为准** —— 同一批模板在不同工程里编号就是不一样

## 挂完先看这几行日志

勾选【日志】→【客户端脚本】，进关卡后应该有：

```
[Chess] 棋子图元：6 种 × 2 方，单枚最多 34 个控件
[Chess] 界面构建完成：控件 1489 个，画布 1600x900，格宽 87.8 界面=start 档位=3
[Chess] 已注册联机信号接收：ChessSync
[Chess] 启动完成：状态=RUNNING 界面=start 控件=1489 联机发送=true 接收=true 同屏=false 档位=3(900+10)
[Chess] [自检] 30/30 通过
```

**三件事按这个顺序看**：

| 看什么 | 意味着 |
|---|---|
| 有 `[Chess] 界面构建完成：控件 1489 个` | 脚本装上了、界面搭出来了 |
| 有 **`[Chess] [自检] 30/30 通过`** | **健康检查通过，可以直接玩**（这行是 v2.0 新增的） |
| 显示 `N/30 通过，失败 M 项` 并跟着 `✗ 名字(明细)` | 装上了但有断言不满足。**把那几行 `✗` 发回来**，那是最有用的诊断信息 |

> 控件数 **以你实际看到的为准**（1489 是 v2.0 在模拟器上的实测值，**真机未验证**）。
> 与 1489 不同不要紧，差几十个通常只是模板差异；**完全没有这行**才是没装上。

## 以后要更新脚本怎么办（**这一节很容易踩坑，务必先读**）

挂好之后，游戏脚本还会更新（修 bug、加功能）。**不要直接覆盖**。

### ⚠️ 最大的坑：交付版里的 4 个索引是 `0`

`out/交付包/levelScript.lua` 是**交给你之前的原始态**，第 **37~40 行** 是：

```lua
CONTAINER_NODE_INDEX = 0,      -- ← 你填过的值会被冲回 0
PREFAB_TEXT_BOX      = 0,
PREFAB_CURSOR_AREA   = 0,
PREFAB_IMAGE         = 0,
```

**如果你把新版 `levelScript.lua` 整个覆盖过去，这 4 行就回到 `0`** ——
进关卡后脚本会打印「界面零件还没配好」然后停机。**这不是新版本坏了，是你的编号被冲掉了。**

### 正确的更新方式（二选一）

**方式 A（推荐，最省事）：只替换改动的那几行**

1. 打开你**已经在用的**那份 `levelScript.lua`（编辑器映射指向的那个文件路径）
2. 对照新版，只把**改动的地方**贴过去 —— **跳过第 37~40 行**
3. 保存 → 编辑器里不需要重新挂脚本，重新进关卡即可

**方式 B（省心但要多一步）：整份覆盖，然后重填索引**

1. 整份覆盖
2. **立刻回第 37~40 行，把 4 个编号填回去**（编号抄你上一版的，或者从编辑器上重新看）
3. 保存 → 进关卡

> **怎么找你上一版的编号**：如果你把映射指向的是自己保留的副本，先备份一份再覆盖；
> 或者在覆盖前把第 37~40 行抄下来。

### 改完怎么确认真的生效了（**别只看"没报错"**）

按顺序看这三条：

| 日志 | 说明 |
|---|---|
| `[Chess] 界面构建完成：控件 1489 个 …` | 脚本是新的（控件数、`界面=`、`档位=` 都是 v2.0 字段） |
| `[Chess] [自检] 30/30 通过` | 新代码跑通了全部 30 条断言 |
| `[Chess] 启动完成：… 档位=3(900+10)` | 档位参数正常 |

> **「没报错」不等于「新代码生效了」** ——
> 如果脚本没重新加载，日志会**和上一版一模一样**，也是"没报错"。
> 所以判据必须是**新版本的特征**（比如 v2.0 才有 `界面=` 字段、才有 `[自检]` 行）。
> 这就是为什么每次更新后都要核对上面那三行。

### 更省事的长期做法：把脚本映射指向一个固定文件

脚本映射绑的是**一个文件路径**。只要你一直改那个文件、不改映射，编辑器每次重新进关卡都会读新内容。
所以长期来看：**把映射指向你自己维护的那一份**（已填好索引），
以后拿到的更新只按「方式 A」往里贴改动 —— **编号永远不用再管**。

## 最常踩的 6 个坑

| 症状 | 大概率是 | 详见 |
|---|---|---|
| 什么都没出现 | 4 个索引里有 `0` | [5.3](导入方案.md#53-三个必须记住的规矩) |
| 界面正常但**点什么都没反应** | 容器 `showCursor` 没开 / 命中区 `raycastTarget` 没写 / 命中区被盖住 | [第 9 节 #08~#10](导入方案.md#第-9-节故障排查表30-条) |
| 棋盘有格子但**没有棋子** | `PREFAB_IMAGE` 填错，或填成了图片**素材**编号 | [5.5](导入方案.md#55-填错的症状对照表) |
| 脚本不运行 | 挂到了客户端控件**模板**上，不是**容器节点** | [第 6 节](导入方案.md#第-6-节脚本挂载) |
| 联机对方没反应、日志无报错 | 用了【发送信号】而不是【**发送客户端脚本信号**】 | [7.4](导入方案.md#74-发送信号和发送客户端脚本信号-两个极像的节点别选错) |
| 结算后点「再来一局」「复盘」没反应 | 弹窗层级问题（**真机专属**，见导入方案的已知限制） | [10.6 ①](导入方案.md#106-v20-已知限制读之前先知道这些能省很多困惑) |

## 两个「不用做」

| 有人告诉你 | 实际情况 |
|---|---|
| 「要建 12 个 `piece_*.lua` 脚本映射」 | ❌ **不用**。v1.7 起棋子数据已内嵌进主脚本（`PIECE_ART` 表），`require` 出现 **0 次**。只需 **1 个**映射，指向 `levelScript.lua` |
| 「要建『预设按钮』模板」 | ❌ **不用**。面板按钮 = 文本框 + 光标检测区域拼的 |
