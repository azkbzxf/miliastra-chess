# 跨会话复盘存档 · 配置方案（需用户在编辑器手动完成）

> 目标：让「单人复盘练习」能读到**上一次进关卡时打的最后一局**，而不只是本次会话的最近一局。
> 这份文档是给**你（关卡作者）**在千星沙箱编辑器里操作的清单。
> 代码侧已经备好接口，你不配置也能玩，只是复盘范围退化为「本会话内最近一局」。

---

## 一、为什么必须由你手动配置

| 能力 | 客户端 Lua | 说明 |
|---|---|---|
| 读写文件 | ❌ | `io.*` 在千星运行时**不可用**（官方《客户端控件API文档》§三「运行环境」明列） |
| 写全局自定义变量 | ❌ | 自定义变量只能由**服务端节点图**写入；客户端只能读 |
| 读全局自定义变量 | ✅ | 客户端可读，但要你先把变量建出来 |
| 跨关卡会话保留 | ❌ | 纯客户端内存，退出关卡即清零 |

所以「跨会话」这件事**只能靠服务端变量**，而服务端变量必须在编辑器里手动建。

---

## 二、需要建的东西（两样）

### 2.1 三个全局自定义变量

在编辑器里新建 **字符串** 类型的全局自定义变量：

| 变量名 | 类型 | 用途 |
|---|---|---|
| `ChessLastFen` | 字符串 | 上一局终局局面的 FEN |
| `ChessLastMoves` | 字符串 | 上一局的走子序列（压缩格式，见 2.3） |
| `ChessLastMeta` | 字符串 | 上一局元信息：结果 / 档位 / 时间戳 |

> ⚠️ **变量名必须逐字一致**（大小写敏感）。代码里读的就是这三个名字。

### 2.2 一条服务端节点图规则

新增一条信号规则，接收客户端信号 `ChessArchive`：

```
触发：收到客户端脚本信号 ChessArchive
动作：把参数 a（字符串）写入全局自定义变量，按参数 b 分派：
      b == 0 → ChessLastFen
      b == 1 → ChessLastMoves
      b == 2 → ChessLastMeta
```

参数约定（5 个槽位与现有 `ChessSync` 同形）：

| 槽 | 类型 | 含义 |
|---|---|---|
| `a` | 字符串 | 要保存的内容（FEN / 走子串 / 元信息） |
| `b` | 整数 | 目标变量编号 0/1/2 |
| `c` `d` | 整数 | 预留，填 0 |

> **只写不广播**。这条规则**不要**加 `sendClientScriptSignal` —— 存档是单向写入，
> 广播回所有玩家既没必要，也会浪费带宽。

### 2.3 走子串的压缩格式（代码已按此实现，供你核对）

```
"e2e4,e7e5,g1f3,b8c6,..."      // 每步一个 UCI 四字符，逗号分隔
```

FEN 单条长度上限按平台字符串变量限制（通常 ≥ 256 字符足够存一个局面）。

## 三、代码侧已经就绪的部分（你不用管）

| 位置 | 已有能力 |
|---|---|
| `settle_match_record()` | 结算时把整局快照深拷贝到 `GAME.lastArchived`（内存） |
| `entry_start_review()` | 有存档 → 从 `GAME.lastArchived` 重建时间线并停在最后一步；无存档 → 退回「开局演练」 |
| `EV_RESULT` 协同 | 双方都选「复盘」才进复盘（已实现，不依赖本节配置） |

**尚未实现、需要你确认后我再加的部分**：把 `GAME.lastArchived` 通过 `ChessArchive`
信号发给服务端、以及启动时读回三个变量。**这两段我没写**，因为：

1. 它们完全依赖你在编辑器里建好的变量名与规则是否匹配；
2. 我无法在模拟器里验证真机的变量读写（模拟器没有服务端变量环境）；
3. 写进去但变量不存在时，代码会静默失败，反而让人以为「配了也没用」。

**所以流程是**：你按第二节建好 → 告诉我变量名有无差异 → 我再把读写两段加上 →
真机试玩确认「退出关卡再进来，点复盘能看到上一局」。

## 四、验证清单（你建好后用来确认）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 打完一局（将死/认输/和棋任一） | 结算面板出现，比分行有数字 |
| 2 | 点「退出」回初始界面 | 回到初始界面，无对手在线 |
| 3 | 点「单人·复盘研习」 | 有存档 → 直接停在**上一局最后一步**；无存档 → 从开局起 |
| 4 | 退出关卡，重新进入 | 若第三节读写已加上 → 仍能复盘到上一局；未加 → 提示从开局演练 |

## 五、如果不想配（退化行为）

不配置完全能玩，行为如下：

- 「单人·复盘研习」始终读**本会话内**最近结束的那一局；
- 刚进关卡（还没打完一局）时，进复盘会提示「还没有上一局」并从开局演练；
- 积分（比分行）只在本会话累计，退出关卡清零。

**这三条都是可接受的退化，不是 bug。** 用户需求里「胜利的加分」本就选定为会话内累计；
只有「复盘读上一局」在跨会话这一层需要你配置。
