## 二、棋子是怎么来的（为什么不是图片）

千星奇域的图片控件**只能**用官方白名单素材或元件图标，**没有上传自定义图片的入口**，
官方白名单里也没有国际象棋棋子。所以本项目的棋子是「图元拼」出来的：

```
兵 = 矩形(底座) + 矩形(身) + 三角(腰) + 矩形(颈) + 圆(头)
车 = 矩形 ×8（底座/颈/身/颈环/冠带/三个垛口）
马 = 矩形(底座/颈) + 旋转矩形(粗颈/斜脸) + 三角(口鼻/耳) + 圆(头顶)
象 = 矩形(底座/颈环) + 圆×3（扁身/主教帽/顶球）
后 = 矩形(底/裙环/冠带) + 圆(身/裙) + 三角×5(冠尖) + 圆×5(冠顶珠)
王 = 矩形(底/颈/颈环/冠带/十字) + 三角(身) + 圆(冠球)
```

每枚棋子先画一层「放大 15.5% 的深色版」当描边，再画本体，
得到 cburnett 的「白底黑边」观感。32 枚全盘约 480 个图片控件。

**v1.3：棋子只保留这一种画法。** 原来的「圆盘+棋符」「纯棋符」两档已按用户要求删除，
连带删掉样式切换按钮（面板由 5 个按钮变为 4 个）、`PIECE_GLYPH` 表与 `GAME.pieceStyle` 状态。
现在**不依赖任何 Unicode 棋符字体**，也不再有「棋符显示成方框」的风险。

**副作用**：`PREFAB_IMAGE` 由「可选」升为**必填**，已加入 `validate_config()` 启动校验——
缺它时棋盘上不会有任何棋子，直接报错比让用户对着空棋盘猜要好。

## 四、挂载说明（**这一步必须由你做，漏了就完全跑不起来**）

### 4.1 先把脚本导入编辑器

1. 打开「千星沙箱」
2. 点右上角「窗口」，再点「客户端脚本资源管理器」
3. 任选一个文件夹，右键
4. 选择「批量添加脚本文件」→「按文件」
5. 选中 `levelScript.lua`，点「打开」
6. 显示「添加成功」就完成了

### 4.2 填 3 个编号（**不填会报「界面零件还没配好」**）

用记事本打开 `levelScript.lua`，找到文件开头第 1 区的 `CONFIG`，把下面三行的 `0` 换成真实编号：

```lua
CONTAINER_NODE_INDEX = 0,      -- ← 换成容器节点索引
PREFAB_TEXT_BOX      = 0,      -- ← 换成文本框模板索引
PREFAB_CURSOR_AREA   = 0,      -- ← 换成光标检测区域模板索引
```

**这三个编号怎么拿**：

| 编号 | 怎么读 |
|---|---|
| 容器节点索引 | 「界面控件组管理」→ 找到你建的「客户端控件容器」→「画布设置」→「前往编辑」→ 选中「容器节点」→ 点右上角「复制」，复制到的就是 |
| 文本框模板索引 | 「界面控件组库」→ 切到「客户端控件模板」→ 点左下角「添加客户端控件」→ 选「文本框」→ 保存 → 读它的编号 |
| 光标检测区域模板索引 | 同上，选「光标检测区域」→ 保存 → 读编号 |
| **图片模板索引（必填）** | 同上，选「图片」→ 保存 → 读编号，填 `PREFAB_IMAGE`。棋子全部用图元绘制，缺它棋盘上不会有棋子 |

### 4.3 把脚本装到界面上

1. 回到「原神」窗口，打开「界面控件组管理」
2. 找到你建的「客户端控件容器」，点「画布设置」→「前往编辑」
3. 选中「容器节点」
4. 在右边切到「脚本」页签，点「添加脚本」，选 `levelScript`
5. 保存
6. 进关卡试一下

### 4.4 服务端节点图（联机必须，本地同屏不需要）

联机对战需要服务端把一端的走子广播给另一端。**这部分不在我们提供的接口文档里，需要你在编辑器里搭一个很简单的节点图**：

```
收到信号 ChessSync（5 个参数：整数、整数、整数、整数、字符串）
  → 广播信号 ChessSync（把这 5 个参数原样发出去，目标＝房间内所有人）
```

要点：
- 信号名必须是 `ChessSync`（大小写一致）
- 参数顺序必须是：`整数 → 整数 → 整数 → 整数 → 字符串`
- 广播目标必须是「房间内所有人」，不能只回给发送者
- 节点图**不做任何校验、不存数据、不排序**，收到就原样广播

**搭不出来也没关系**：脚本会自动退化为「同屏轮流」模式，两位玩家共用一块屏幕轮流点，功能完全一样。

## 五、联机信号协议（给搭节点图用）

| eventType | 含义 | a | b | c | fen |
|---|---|---|---|---|---|
| 0 | 走子 | 起点格号 0–63 | 终点格号 0–63 | 升变：0=非升变 1=后 2=车 3=象 4=马 | 走子后的完整局面 |
| 1 | 新局 | 0 | 0 | 0 | 初始局面 |
| 2 | 认输 | 认输方 0=白 1=黑 | 0 | 0 | 空串 |
| 3 | 求和 | 发起方 0=白 1=黑 | 0 | 0 | 空串 |
| 4 | 同意和棋 | 同意方 0=白 1=黑 | 0 | 0 | 空串 |
| 5 | 请求加入 | 0 | 0 | 0 | 空串 |
| 6 | 身份分配 | 0=你是白方 1=你是黑方 | 0 | 0 | 空串 |
| 7 | 拒绝和棋 | 拒绝方 0=白 1=黑 | 0 | 0 | 空串 |

**格号约定**：格号 = 行号 × 8 + 列号。行 0 = 第 1 横排（画面最下一排），列 0 = a 列。
所以 `a1 = 0`，`e2 = 12`，`e4 = 28`，`h8 = 63`。

## 八、素材编号与来源

### 8.1 棋子怎么画的（不用任何自定义图片）

**千星奇域的图片控件不能上传自定义图片**，只支持两种来源：

| 来源 | 说明 |
|---|---|
| `StaticReference`（静态引用） | 官方预设素材，**固定白名单**，编号只能从白名单里挑 |
| `Prefab`（元件） | 编辑器里自建的元件图标 |

已全量下载核查官方白名单 **1517 个素材**（`tools_work/icons/catalog/`），按英文名搜 chess/pawn/knight/rook/bishop/queen/king 与中文「棋」**全部 0 命中**；灰度/竖高/形状三轮筛选后肉眼复核联系表，全是 UI 图标，**没有任何国际象棋棋子**。

平台里唯一能上传 PNG/JPEG 的地方是「自定义小地图」（月之七新增，16×16~2048×2048 px、单张 ≤5MB），**只服务于小地图控件**，普通图片控件用不上。

因此棋子改为**用官方基础图元拼**，不依赖任何自定义素材，也不依赖任何字体：

```lua
PIECE_ASSET = {
  RECT   = 100001,   -- 官方实心矩形图元，可染色可拉伸可旋转
  CIRCLE = 100002,   -- 官方实心圆图元，可染色可拉伸成椭圆
  TRI    = 100003,   -- 官方实心三角图元，可染色可旋转
}
```

| 档位 | 组成 | 控件/枚 | 需要 PREFAB_IMAGE |
|---|---|---|---|
| 图元拼（**唯一档**） | 描边层 + 本体层，共用同一个 15 控件池 | ≤15 个图片控件 | **必填** |

- **`PREFAB_IMAGE` 是必填项**。填 0 时 `validate_config()` 会在启动阶段直接返回失败并报
  「`PREFAB_IMAGE（棋子用图元绘制，必须建「图片」控件模板）`」，不做无意义重试。
- 白黑共用同一套几何，只换颜色：白子 = 白色填充 + 深色描边，黑子 = 深色填充 + 浅色描边。
- 每枚先画一层按棋子中心放大 `1.155` 的深色版作描边，再画本体压在上面。
- `PIECE_MAX_SLOTS = 32`，每槽 `PRIM_MAX = 15` 个图片控件，**播放期零创建零销毁**，
  只改尺寸/位置/颜色/显隐。

### 8.2 非图片部分（不用编号）

棋盘格、高亮、面板、按钮全部由文本框的底色与文字自绘：
- 棋盘格 = 64 个文本框，`text=""`，`bgColor` = 浅格 `(238,228,208)` / 深格 `(106,130,150)`
- 高亮/面板/按钮 = 文本框 + 盖在上面的光标检测区域
- 只读文本（棋钟、记谱、吃子记录、提示条）= 普通文本框

### 8.3 棋子样式不再可切换

v1.3 起只有一种画法，面板按钮由 5 个减为 4 个（新开一局 / 认输 / 求和 / 切换本地同屏）。
`GAME.pieceStyle`、`CONFIG.PIECE_STYLE_CYCLE`、`piece_style_*()` 全部移除。

## 十一、已知限制

| # | 限制 | 说明 |
|---|---|---|
| L-1 | **联机需要你自己搭服务端节点图** | 服务端接口不在我们提供的文档里。搭不出来会自动退化为同屏轮流，不影响玩 |
| L-2 | **不能用自定义棋子图片** | 平台图片控件只支持官方白名单素材与元件图标，无上传入口；已核查 1517 个白名单素材无国际象棋棋子。故棋子改用「官方矩形/圆/三角图元」拼，只有这一种画法 |
| L-2b | **`PREFAB_IMAGE` 是必填项** | v1.3 删除圆盘/符号两档后，没有「不用图片控件」的兜底了。缺它时 `validate_config()` 启动即报错，棋盘上不会有棋子 |
| L-3 | 联机身份分配依赖服务端按顺序回广播 | 服务端做不了就退化为「先进入者白、后进入者黑」 |
| L-4 | 手柄操作未验证 | 手柄导航依赖编辑器内置能力，未在真机确认；键鼠与触屏不受影响 |
| L-5 | 中文渲染宽度未在真机确认 | 全部文案按 ≤20 汉字保守设计 |
| L-6 | 联机时两端棋钟可能有 1 秒级差异 | 走子信号携带剩余时间，收到即覆盖 |
| L-7 | 沙箱与真机的 `raycastTarget` 差异 | 沙箱未实现该字段读写，正式文件里已开启（`CONFIG.ENABLE_RAYCAST_FIELD = true`），真机生效 |
