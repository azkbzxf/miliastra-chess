## 这一版改了什么

**棋子改成「12 份拟合数据」驱动**（v1.5）。

- 你提供的 12 个文件（PW/PB/BW/BB/NW/NB/RW/RB/QW/QB/KW/KB）每份 400 个图元，
  是 Miliastra-toolbox-primitive-shape 填充模式对 512×512 源图的拟合结果。
- 这 12 份文件**一个数字都没改**，只把尾部的「自己挂载、自己建控件」那段换成
  `return {...}` 数据表，好让主脚本统一加载。
- 每枚棋子只用其中 `PIECE_PRIM_BUDGET = 40` 个图元（32 枚 = 1280 图片控件）。
  调这个数字就能在「更保真」与「控件更省」之间取舍。
- 旧的 `pieces_pixel.lua`（手排形状表）已从包里移除；旧表仍留在脚本源码里作对照，
  运行期不再读取。

**三处必须知道的换算**（都写在 `交付说明.md` 与 `docs/tech-architecture.md`）：

1. 原数据 `cy` 是负值（导出器 y 从图片顶部往下量），归一化要 `ny=(cy+H)/H`。
2. 拟合把「白底纸」也拟进了数据，必须按暗色元素定范围后剔除，否则每枚带白方块。
3. 拟合器会输出伸到画布外的图元，必须先丢弃，否则包围盒被撑大、棋子被压扁。

**为什么不用真实棋子图**：千星奇域的图片控件只支持官方预设素材白名单与元件图标，
**没有上传自定义图片的入口**。已全量核查 1517 个白名单素材，无任何国际象棋棋子。

## 怎么开始

**先玩网页版**：双击 `chess_demo.html`，白方先走（点棋子 → 点亮格子）。

**再装进游戏**：打开 **`挂载指南.md`**，照着做 6 件事：

1. 建一个「客户端控件容器」
2. 把 `levelScript.lua` 导入沙箱并挂到容器节点上
3. 建 3 个控件模板（文本框 / 光标检测区域 / 图片）
4. **建 12 个脚本映射**指向 12 个 `piece_*.lua`（只建映射，**不要挂载**）
5. 填 4 个编号进脚本 CONFIG
6. 保存并试玩

**想联机**：再看 `交付说明.md` 第五节 → 搭一个「收到就转发」的节点图
（不搭也能玩，会变同屏轮流）。

```

  piece_PW piece_PB piece_BW piece_BB piece_NW piece_NB

```

## 已修掉的缺陷（沙箱全测不出来）

| 缺陷 | 现象 | 根因 |
|---|---|---|
| F-1 | 棋子重叠、串到隔壁格 | `create_image` 用 pivot=(0,0)，渲染却按中心算位置 |
| F-2a | **点击完全没反应** | 跳过写 `raycastTarget` → 光标区收不到任何事件 |
| F-2b | **点击完全没反应** | 命中区被后建的棋子/面板盖住（同级后出现者在上） |
| F-3 | — | `SetVisible` 未显式置真 |
| F-4 | 面板按钮点不动 | 同 F-2b |
| D-01 | 黑方回合白方认输，显示「**黑方**点了认输」 | 认输方按「轮到谁」判，应按「谁点的按钮」 |
| D-02 | 结算面板只有说明行，**标题一片空白** | 标题框高 64.8px < 字号 44 所需 72.6px，整行被吞 |
| D-03 | 收到求和弹「重开会清空这一局」；发起方自己弹框；和棋标题空白 | `show_confirm()` 缺 kind；广播含发送者自己；键名多打 `_AGREED` |
| D-05 | 走子后日志报「收到无法验证的走子信号」 | 自己的走子广播回自己被当对方走子重算 |
| D-06 | 每枚棋子带一圈白方块 / 光晕大圆 | 拟合把白底纸与羽化光晕也拟进了 `ELEMENTS` |
| D-07 | 色块散开成「爆炸」状飞出格子 | 图元 pivot=(0,0)，而 `SetLocalRotation` 绕 pivot 旋转 |
| D-08 | 黑兵下方灰色椭圆、整枚棋子被压扁 | 暗色阈值过松把过渡灰当墨迹；越界块把包围盒撑高 24% |

> **教训**：体外沙箱没有光标命中测试，「沙箱 17/17 通过」只能证明规则和内存正确，
> **不能证明界面能点**。交互类结论一律以模拟器/真机为准。
> D-01～D-08 这八个缺陷在沙箱里全是绿的。
> D-06～D-08 更进一步：数据合法、API 全成功、沙箱不报错，**只有截图才看得见**。
