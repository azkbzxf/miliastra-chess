## 三、⚠️ 三个最容易搞错的地方

### ① 那 12 个 `piece_*.lua` **不用建映射、不用挂载**

**这是 v1.5 时代的做法，v1.7 起已废弃。**
棋子数据现在**内嵌在主脚本里**（`PIECE_ART` 表），脚本里 `require` 出现 **0 次**。

> **只需要建立 1 个脚本映射**，指向 `levelScript.lua`。
> 如果你照着旧教程建了 12 个映射，**不会坏事，但完全没必要**。

### ② 4 个索引必填，缺一个就停机

```lua
CONTAINER_NODE_INDEX = 0,   -- 容器节点索引
PREFAB_TEXT_BOX      = 0,   -- 文本框模板索引
PREFAB_CURSOR_AREA   = 0,   -- 光标检测区域模板索引
PREFAB_IMAGE         = 0,   -- 图片控件模板索引（棋子靠它绘制）
```

填**模板最外层**的编号，**不是**模板内部子控件的编号。
**以你编辑器上显示的为准** —— 同一批模板在不同工程里编号就是不一样。

### ③ **以后更新脚本不要整份覆盖**

交付版的第 37~40 行是 `0`。你整份覆盖新版，这 4 行就被冲回 `0`，脚本会打印
「界面零件还没配好」并停机 —— **看起来像新版本坏了，其实是你的编号被冲掉了**。

正确做法见 `挂载指南.md` §「以后要更新脚本怎么办」。

## 六、已修掉的缺陷（都是「沙箱全绿但真实存在」那类）

| 缺陷 | 现象 | 根因 |
|---|---|---|
| F-1 | 棋子重叠、串到隔壁格 | `create_image` 用 pivot=(0,0)，渲染却按中心算位置 |
| F-2a | **点击完全没反应** | 跳过写 `raycastTarget` → 光标区收不到任何事件 |
| F-2b | **点击完全没反应** | 命中区被后建的棋子/面板盖住（同级后出现者在上） |
| D-01 | 黑方回合白方认输，显示「黑方点了认输」 | 认输方按「轮到谁」判，应按「谁点的按钮」 |
| D-02 | 结算面板只有说明行，**标题一片空白** | 标题框高 < 字号所需，整行被吞（**板高须 ≥ 2.1×字号**） |
| D-05 | 走子后报「收到无法验证的走子信号」 | 自己的走子广播回自己被当对方走子重算 |
| D-06~08 | 每枚棋子带白方块 / 色块「爆炸」状 / 被压扁 | 拟合数据含底纸与羽化；pivot 与旋转中心不一致 |
| **v2.0 P0** | **结算面板整块点不动** | `hitOverlay` 是 1600×900 全屏命中区，却被**最后**抬起 → 盖住了两个按钮 |
| **v2.0 P1** | 结算「复盘」一步未走时静默失效 | `enter_review()` 缺 `allowEmpty` |
| **v2.0 P1** | **「自检全绿」曾经是假的** | `SelfTest()` 定义了但**全项目 0 处调用** |
| **v2.0 P2** | 进对局/再来一局后第三行停在「看历史」 | `new_game()` 不刷悔棋按钮，且它跑在 `screen="playing"` 之前 |

> **教训**：体外沙箱没有光标命中测试，「沙箱通过」只证明规则与内存正确，
> **不能证明界面能点**。交互类结论一律以模拟器/真机为准。
> **更要紧的一条**：v2.0 之前「自检 30 条全绿」是**从未执行过**的假绿 ——
> **断言写了不跑，等于没写。**
