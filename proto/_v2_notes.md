## 三、「板高 ≥ 2.1 × 字号」—— 本次最重要的结构改动

### 规则本身

```
板高 ≥ 2.1 × 字号     （行高 1.2× + 上下内边距 0.9×）
```

**违反的后果不是截断，而是整行被吞掉、什么都不显示、也不报错。**
本项目已踩三次：① v1.10 结算面板标题 ② v2.0 块 1 的档位名 ③ gdd §5.6 倒数数字 72。

### 我加了断言，它当场抓出 26 处真实违规

第一次跑 `v2_text_box_height_ge_2_1x_font`，报了 **26 个控件不合格**，例如：

```
v2starttitle  h=94.5  字号=76.0  需≥159.6   文=[黑白棋局]
v2cardname1   h=55.2  字号=34.0  需≥71.4    文=[超快棋]
v2cardline*   h=44.1  字号=22.0  需≥46.2    文=[首钟：1 分钟]
v2lobbycountdown h=96.3 字号=60.0 需≥126.0  文=[即将开始 1]
```

**这不是误报 —— 按规则这些文字真的会在真机/浏览器里整行消失。**

### 修法：不再手写任何文本高/字号字面量，只走两个互逆方向

```js
const V2_H_RATIO = 2.1;
const fitH     = (base) => Math.ceil(font(base) * V2_H_RATIO) + 1;  // 字号 → 高度
const fontForH = (hPx)  => Math.max(MIN_FONT, Math.floor(hPx / V2_H_RATIO)); // 高度 → 字号
```

| 场景 | 走哪条 |
|---|---|
| 自由漂浮的单行文字（标题/副标题/分组标签/提示/落款） | `fitH(base)` 由字号反推高度 |
| 容器内均分的文字行（档位卡四行/待机室玩家行/动作条按钮） | `fontForH(h)` 由行高反推字号 |

两者互为逆运算 → **无论哪条路径都不可能 ratio < 2.1**。断言遍历实测兜底。

### 连带修掉的第二个问题：纵向排布

旧写法 `titleY = canvasH * 0.845` 是「比例定位」，而标题 76 号字需要 161px 高 ——
`0.845 × 900 + 161 = 921`，**直接飞出 900 高的画布**。

改成**单来源推导**：只有一个 gap 数组 + 每段自己的 `fitH`，从画布顶端往下累加。
再加一条兜底：若算到底部 `cursor < 0`（小画布放不下），整块内容**上移**而不是硬塞。

### 四档画布的复算结果（照抄公式在 Node 里跑）

| 画布 | fontScale | 全部文本 ratio≥2.1 | 内容不越画布 | 段落不重叠 | 动作条不压棋盘 |
|---|---|---|---|---|---|
| pc-16-9 1600×900 | 1.000 | ✅ | ✅ | ✅ | ✅ |
| mobile-16-9 1280×720 | 0.800 | ✅ | ✅ | ✅ | ✅ |
| **mobile-4-3 1280×960** | **0.800** | ✅ | ✅ | ✅ | ✅ |
| pc-21-9 2100×900 | 1.000 | ✅ | ✅ | ✅ | ✅ |

## 十二、⚠️ Demo 与 Lua 的布局数据**不要求一致**（重要，防将来对错表）

**这一节请务必转给 design-lead，避免 GDD 把某一侧的像素写成契约后与另一侧打架。**

### 已经出现的事实差异

| 项 | Demo 侧（本文件） | Lua 侧（lua-lead 实测） |
|---|---|---|
| 档位卡宽度 | `contentW` 的 1/4 再减间隙（1600 画布下约 289px） | `TC_CARDS` 卡宽 **302.7px** |
| 档位名高度 | **55.2px** | **60.3px** |
| 档位名字号 | **34** | **28** |

**两边尺寸不一样，这是可接受的，而且不应该去「修」成一样。**

### 为什么允许不一致

| | Demo（本文件） | Lua（交付件） |
|---|---|---|
| 角色 | **体验沟通件** —— 让人看懂「长什么样、怎么交互」 | **交付件** —— 真正跑在千星里 |
| 约束 | 浏览器 CSS 布局，自由度大 | 平台控件数 1600 上限、无 border/圆角/阴影、pivot 不同 |
| 目标 | 观感与流程正确 | 在真实平台约束下可用 |
| 几何 | 各按自己的画布自适应算 | 各按自己的画布自适应算 |

Demo 里一个控件能画圆角边框，Lua 里要拆成 3 个控件；Lua 为了省控件把卡内四行合成一个多行文本框，Demo 不必。
**硬把两侧像素对齐，等于要求一方违背自己的平台约束。**

### 唯一需要两侧**逐字/逐值一致**的是这些（其余都不要求）

| 类别 | 具体要求 | 谁来守 |

| **文案逐字** | `TEXT` + `TEXT_V2` 全部字符串，含全角括号/冒号/空格/省略号/en-dash | `consistency_check.cjs` 的文案逐字比对 + Demo 自检第 20 条 |
| **逻辑数值** | 四档首钟秒/加秒秒（60+0/180+2/900+10/5400+30）、悔棋每方 3 次、倒数 3 秒 | Demo 自检第 1~4 条 + Lua 侧 `TIME_CONTROLS` 断言 |
| **状态机语义** | start/lobby/playing/result/review 五态与转移、悔棋四条边界、分支不污染主变 | Demo 自检第 12~16 条 + Lua 侧等价断言 |
| **联机事件号** | 8~13 号事件的参数含义（第十节表） | 两侧人工对齐 |
| **配色 RGB** | `COLOR` 表的 rgb 三元组（视觉语言统一） | `consistency_check.cjs` 配色 17 项 |
| **字号基准** | `FONT` 表那 **10 个**被门禁覆盖的键（COORD/PIECE/PANEL_TITLE/PANEL_BODY/CLOCK/BUTTON/HINT/RESULT_TITLE/RESULT_SUB/PROMO_OPTION） | `consistency_check.cjs` 字号十项 |
| **v1 面板布局** | `PANEL_LAYOUT` 那 11 项的 `{y, h}` | `consistency_check.cjs` 布局表比对 + CHECK-6 |

> **`FONT.V2_*` 那 8 个 v2 新字号（V2_TITLE / V2_SUB / V2_CARD_NAME / …）不在门禁覆盖范围内** ——
> 它们只是 Demo 的排版输入，Lua 侧可以按自己的控件尺寸另定。
> 若将来要纳入门禁，需同时改 `consistency_check.cjs` 的 `fontKeys` 数组，别只改一边。

### 一句话结论

**拿 Demo 的像素去核对 Lua 的实现是错误做法。** 应核对的是：文案是否逐字、四档秒数是否对、悔棋次数与边界是否对、状态机转移是否对。**视觉尺寸各按各的画布自适应。**
