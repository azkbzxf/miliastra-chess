### 两处工程教训（都曾真实造成破坏）

**① 静默失败是最大的一类危险**
`sfx_play("over")`、`shot.ps1` 截图截错窗口仍返回 `SHOT_SAVED` —— 同一个模式：
**报「成功」但没有做对事**。修法不是「小心一点」，而是让错误变显式：
`sfx_play` 现在对未知键名 `log_err`（每键一次）；截图脚本应断言输出尺寸 == 请求尺寸。

**② 断言方向也可能写反**
`consistency_check.cjs` 的音效断言原本检查「`sfx_play("<Demo键名>")` 字面量是否存在」，
于是 **bug 存在时 PASS、bug 修好后 FAIL** —— 完全反向。已改成「调用点参数能否解析到
`CONFIG.SFX` 的真实键」，与运行时解析规则一致。
> 教训：断言要验「**语义是否成立**」，不要验「**某个字符串在不在**」。

**B. 走子提速（已完成）**

用户反馈「动画不跟手、响应慢」。根因是 `OnUpdate` 动画期间每帧全量 `render_pieces()`：
32 枚 × 每枚约 10 图元 × 3~4 次控件写 ≈ **每帧数千次控件写**。

- **脏槽位局部重绘**：`anim_add(dur, fn, onDone, slot)` 第 4 参声明「我改这个槽位」，
  `anim_update` 登记脏槽位（slot 表做 key 去重），OnUpdate 只重绘脏槽位；
  `render_pieces(onlySlots, onlyCount)` 加快速路径跳过 bySq 重建与整盘遍历。
- **A/B 实测**（e2→e4 一步，数字来自 `GetRepaintStats`）：
  旧 `full=10 partial=0` → 320 次 paint_slot；新 `full=2 partial=8 slots=8` → **72 次**。
  动画期控件写约降 **78%**，稳态每帧 32 槽 → **1 槽**。
- **为什么不会漏绘**：槽位归属只在全量 render_pieces / apply_move / reset_piece_slots 改，
  这三处之后都走全量渲染；动画只改 x/y/scale/lift。动画结束按 `needsRepaint` 补一帧全量收尾。
- **时长对齐 Demo**：`MOVE_DUR 0.24→0.17`、`SETTLE_DUR 0.14→0.10`、`SETTLE_PEAK 0.10→0.07`。
- ⚠ **任务卡没提的坑**：Lua 回弹曲线 `1+sin(v·π)·(1-v)·PEAK` 里 `sin(v·π)·(1-v)` 的真实峰值
  只有 **0.579230**，直接乘 0.07 只能弹到 **4.05%**（不是 Demo 的 7%），等于「既变快又变平」。
  新增 `SETTLE_NORM = 1.726429` 归一，实测峰值正好 **7.000%**，两端精确为 1.000000。
- `anim_update_hilites` **未动**：它每帧写 ≤29 个小控件，比棋子重绘的 320 次低两个数量级，
  且只在有选中/落点时跑；改它得动 0.09s/个的相位错开逻辑，风险高收益 <10%。

**C. 动画曲线（自绘缓动，不用 `game.Tween`）**

新增「第 5.5 区 ANIM」：`EASE.linear/outCubic/outQuint/inOutSine/outBack`、
`ANIM{tasks,count,clock}`、`anim_add/anim_kill/anim_update/anim_clear`、`color_alpha`。
所有动画都是 `{t, dur, fn, onDone}` 任务，由 `OnUpdate` 单点推进。

| 动画 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 走子 | 0.24s | `outCubic` | 位移 + `sin(πu)` 弧线抬升（MOVE_ARC 0.16 格），落点回弹 0.14s `outBack` |
| 吃子淡出 | 0.28s | `outCubic` | 被吃棋子缩小 + 消失 |
| 选中格脉冲 | 0.95s 周期 | 正弦 | 尺寸 1.00↔1.02、透明度呼吸；上下两条琥珀亮框同步 |
| 落点脉冲 | 1.15s 周期 | 正弦 | 尺寸 1.00↔1.12，逐个错开 0.09s 相位 |
| 开局弹入 | 0.55s | `outBack` | 32 枚按格序 stagger 0.018s |
| 弹窗淡入 | 0.22s | `outCubic` | 透明度 + 上浮 0.035 |

**为什么不用平台缓动**：一枚棋子是一个槽位 = 十几到三十几个图片控件，
必须让同一枚的所有图元**跑同一条时间线**，否则棋子会在动画中途散架。
自绘任务表可以一次 `paint_slot` 重画整枚。

**D. 三处只有跑起来才暴露的缺陷（runtime=simulator）**

- **D-12 走子后棋子不动**：`ANIM` 只更新 `slot.x/y` 这些数据，真正写控件的是 `paint_slot`，
  而它只在 `render_pieces` 里被调用。原实现只推进动画不重绘，于是位置数据早已是终点、
  画面还停在起点。修法：`OnUpdate` 里只要有动画在跑就补一帧 `render_pieces()`。
- **D-13 一帧内新建的动画任务被丢弃**：`anim_update` 在遍历后写 `ANIM.count = w`，
  把 `onDone` 里新加的任务（落子回弹接在移动后）直接丢掉，表现为棋子停在半路
  或开局弹入的棋子永远停在 `scale=0.01` 看不见。修法：循环上界用进入本帧时的计数，
  新任务留到下一帧，压缩时把它们接到尾部。
- **D-14 `bgColor` 写到图片控件上**：落点池改成正圆图元（`100002`）后仍是图片控件，
  颜色字段是 `imageColor` 不是 `bgColor`（`bgColor` 只属于文本框），
  点一下就抛 `cannot set bgColor, no such field`，点击全废。修法：按控件类型分开写。

**E. 观感调参（都是模拟器实测结论，别改回去）**

- `PIECE_OUTLINE_PAD` 从 0.030 收到 **0.012**。棋子是宽度差异很大的形状堆叠体，
  整组放大 0.030 会把内部形状边界错开超过一个像素，黑方的鬃毛/冠尖糊成大片浅色斑块；
  0.012 在 81px 棋子方框上约 1px，只有最外廓有一圈细亮边。
- **role2 细节线必须很细**（归一化 ≤ 0.06）。它是实心图形不是描边，
  用 0.30×0.50 的椭圆画鬃毛会变成盖住半个头的色斑。
- 描边层必须**整组绕方框中心等比放大**，不能逐形外扩固定像素 —— 逐形外扩会在
  宽块与窄块交界处留下阶梯状毛边。
