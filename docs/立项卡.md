## 四、关键设计决定（主控已拍板）

| # | 决定 | 理由 |
|---|---|---|
| 1 | **零图片素材**：全部界面用「文本框底色当色块 + 文字当棋子」 | 用户未提供图片编号；图片控件必须 `SetImage(source, id)` 才有画面，缺编号无法显示 |
| 2 | **棋子用字母** K/Q/R/B/N/P（白方浅色、黑方深色） | Unicode 棋符字体支持未确认，字母 100% 可显示 |
| 3 | **联机对战为主模式，本地同屏为备用模式** | 用户选了联机；但服务端接口不在文档内，需保留可在沙箱验证的完整路径 |
| 4 | **联机同步走已文档化客户端能力**：`game.ServerSignal` 发出 / `script:RegisterServerSignalHandler` 接收；服务端「收到即广播」节点图由用户搭 | 服务端接口未文档化，只能这样落地，且必须如实标注 |
| 5 | **服务器信号命名**：客户端发 `ChessMove`（int: 起点、int: 终点、int: 升变、int: 步序）；服务端广播 `ChessSync`；另需 `ChessJoin` 分配先手 | 信号名与参数顺序写进挂载说明，用户按图搭节点图 |
| 6 | **完整国际象棋规则**：易位、吃过路兵、升变、将军、将死、逼和、五十步、三次重复、子力不足 | 棋类玩法的核心乐趣在规则完整度；缺规则会立刻被玩家发现 |
| 7 | **计时**：每方 15:00 基础 + 每步 10 秒加秒（Fisher），超时判负 | 双人对战需要防止长考拖死一局；具体数值见策划案 |
