# 棋子图元拟合报告 —— 算法拟合（cburnett / en-croissant）

本文件由**参数化拟合脚本**生成，不是手调结果。

## 方法与来源

* 参考图：`out/棋子素材-en-croissant/png/256/{KW,QW,RW,BW,NW,PW}.png`
  （cburnett 棋子集，作者 Colin M.L. Burnett，**CC BY-SA 3.0**，
  经 en-croissant 项目分发；本仓库仅以它作为形状参考，未使用任何位图）
* 目标掩膜：`alpha > 128` 后 `scipy.ndimage.binary_fill_holes`。
  **整幅 256×256 直接映射到棋子方框，不逐枚裁剪** —— 这样六枚共享同一比例
  与基线，兵仍然比王矮，比例信息不被破坏。
* 拟合：轮廓驱动的贪心集合覆盖 + IoU 坐标下降精修 + 迭代局部搜索。
  候选 = 内接圆盘（沿中轴扫掠，含长短轴/旋转变体）+ 最大内接矩形
  （直方图极大矩形扫掠）+ apex-up 三角形。
* 光栅化语义与游戏渲染**完全一致**（Y 翻转、三角绕盒中心按 `-rot` 旋转），
  并用**第二个独立实现**逐图元比对过：74 个图元 0 像素差异。

## 判读

* IoU 用**独立实现的第二个光栅器**复算，与拟合器内部数值分开计算；
  两者一致说明这个数字不是拟合器自说自话。
* `recall` = 参考掩膜被覆盖的比例（漏画多少），
  `precision` = 画出区域落在参考掩膜内的比例（多画多少）。
* `docs/pieces-fit-preview.png` 是三排对照：
  (a) 参考掩膜、(b) 拟合并集、(c) 差异图
  （**绿 = 两者都有，红 = 只有拟合，蓝 = 只有参考**）。
* 所有图元都完整落在 0..1 画布内，无一裁切。

## 需要说清楚的三件事

1. **四边形/三角并非凑数。** 车用 17 个图元里 10 个是矩形：
   cburnett 的车的塔身、垛口、底座台阶**真的是直边**，用椭圆拟合会把塔
   磨成圆角，读数立刻变差。后与象的冠尖用三角是唯一的正解。
2. **兵只用了 6 个图元就拿到 0.9924**，因为它的形体本来就简单；
   而后用了 17 个仍只到 0.9835 —— 五个冠尖之间是**尖角凹槽**，
   椭圆并集天然是凸的，凹槽只能用更小的图元一点点逼近，这是本方法
   的固有短板，不是没调够。
3. **这是剪影（role 0），不含镂空与细节线。** 参考图里的眼窝、
   十字、砖缝等内部细节本轮刻意不做。
