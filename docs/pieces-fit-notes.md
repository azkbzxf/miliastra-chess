## 二、为什么是算法拟合，不是手调

v1.7 及更早是手写坐标，连续三轮反馈都是「一团糊」。复盘原因不是调参不够，而是：

> **没有人能用眼睛准确估出十几个椭圆的中心/宽高。**

每一轮手调实际上是在盲猜 20+ 个耦合参数，改 A 必然破坏 B，收敛不了。

v1.8/v1.9 改成算法：从原图提取实心剪影，用**轮廓驱动的贪心集合覆盖**撒图元，
再用 IoU 坐标下降 + 迭代局部搜索精修。光栅化语义与游戏端逐像素一致
（Y 翻转、三角绕盒中心按 `-rot` 旋转），所以 IoU 这个数字可信；
并且用**第二个独立实现的光栅器**复算过：74 个图元 0 像素差异。

## 四、三个必须遵守的约束（踩过的坑）

### 1. 整幅 256×256 映射，**不做逐枚裁剪**

六枚原图画在同一个画框里，共享缩放与基线，所以兵本来就比王矮
（实测 兵/王 = 0.909，拟合后 0.903）。

v1.8 中途改成「按每枚自己的 bbox 裁切再拉伸」，结果**兵被放大到和王一样高**，
比例全丢。改回来才正常。这条不能动。

### 2. 白黑只有一份表，扁平结构 `PIECE_ART[kind]`

cburnett 的白子是细黑描边、黑子是实心填充，但提取时对白子做泛洪填充
（`binary_fill_holes`）拿到描边内部的本体，**两者的实心剪影是同一个**。
所以形状只存一份，双方区别仅在渲染颜色。

**不要**恢复 v1.7 的 `PIECE_ART[side][kind]` 两层结构，也不要 `BLACK_OVERRIDE`。

### 3. `piece_prim_max_of_all()` 必须单层遍历

改成两层 side 遍历会让它在扁平表上返回 `m=0` → 钳到 1 → `PRIM_MAX = 1`
→ 每枚棋子只画一个投影椭圆 → **全盘空白**。这是真实的 bug，v1.9 修掉。

## 五、为什么要矩形和三角，不能全是椭圆

纯椭圆并集画不出**方正的直边**和**尖角凹槽**：

- **车**：cburnett 的塔身、三个垛口、底座台阶**真的是直边**。
  全椭圆拟合会把垛口变成两个圆耳朵（实测过就是这样）。
  所以车的 17 个图元里 10 个是矩形、2 个三角（挖凹槽）。
- **后**：五根冠尖之间是**尖角凹槽**，椭圆并集天然是凸的，凹槽只能用三角逼近。
- **马**：全曲线，14 个里 13 个椭圆，只有 1 个矩形给平底座 —— 这是对的。
- **兵**：形体简单，6 个图元就到 0.9924。

## 六、数据格式

```lua
PIECE_ART[kind] = { { shape, cx, cy, w, h, rot, role }, ... }
```

| 字段 | 含义 |
|---|---|
| `shape` | `0`=矩形 `1`=椭圆 `2`=三角（尖朝上，绕自身中心旋转） |
| `cx`,`cy` | 图元**中心**，`0..1`，**左下原点、Y 向上** |
| `w`,`h` | 相对棋子方框边长（方框 = 棋格宽 × 0.92） |
| `rot` | 旋转角（度），**逆时针为正** |
| `role` | `0`=外形 `1`=镂空 `2`=细节线 |

当前 74 行**全部是 `role = 0`（纯剪影）**。参考图里的眼窝、象的十字、
车的砖缝等内部细节本轮刻意未做 —— 它们需要 role 1/2 的额外图元，
而 81px 的棋格上这些细节本来就看不清。

## 七、渲染：paint_slot 的分层

```
① 投影椭圆（半透明黑，压在底座下）
② 外形描边层：每个 role0 形状各自外扩 PIECE_OUTLINE_PAD，中心不动，画描边色
③ 外形填充层：全部 role0 形状原尺寸，画体色
④ 镂空描边 → ⑤ 镂空填充（该格棋格色）   ← 当前数据没有 role1，这两层空转
⑥ 细节线（role2，对比色）                ← 当前数据没有 role2，这层空转
```

### 描边为什么必须「每个形状各自外扩」，不能「整组绕中心放大」

这是数学结论，不是审美偏好，**别再翻案**：

- 单个形状上两者等价。
- **并集上不等价。** per-shape 外扩 = `∪(Sᵢ ⊕ t)`，而 Minkowski 和对并集可分配，
  所以它**恰好等于** `(∪Sᵢ) ⊕ t` —— 并集整体向外扩 t，**一圈边严格均匀**。
- 绕方框中心等比放大 = `∪(k·Sᵢ)`。各形状到中心距离不同 → 离中心远的被推出去更多
  → **远侧的边比近侧的边粗**，同一枚棋子描边不等宽，看起来"发胖"。

历史坑：交付版曾长期用「绕中心放大」，其注释把 per-shape 记为"反面做法"。
真相是当时的台阶来自**拿一串宽度递减的矩形逼近曲线**，跟外扩算法无关；
改拟合方式后台阶自然消失。两份文件因此漂移过，v1.9 已统一为 per-shape pad。

代码形态（两份文件必须一致）：
```lua
local pad = CONFIG.PIECE_OUTLINE_PAD * sside
...
c:SetSizeDelta(s[4] * sside + pad * 2, s[5] * sside + pad * 2)
c:SetAnchoredPosition(ox + s[2] * sside, oy + s[3] * sside)
```
**不要**引入 `ek` / `rcx` / `rcy` 那套绕中心做法。

`PIECE_OUTLINE_PAD = 0.020`（≈1.6px @ 81px 棋格）：
- 0.030 太粗，黑方鬃毛/冠尖糊成大片浅斑。
- 0.012 太细，**白棋在浅木格上几乎看不见**（白填充与浅格色太接近）。
- 0.020 是让白棋在浅格上也有一圈清晰深边的最小值。

## 八、怎么改棋子形状

1. 改/换原图 → 重新跑拟合（方法与命令见 `docs/pieces-fit-report.md`）。
2. 把产出的 6 张表**整段替换** `lua/levelScript.lua` 的 `PIECE_ART`，
   再把同一段拷进 `sim/levelScript.lua`（两边必须一致）。
3. 在模拟器 `qxqy_studio_play` + 截图确认。**IoU 不能代替肉眼**：
   0.99 的拟合照样可能在某枚棋子上看着别扭。
4. 更新本文第一节的表和 `docs/tech-architecture.md` 的图元计数。
