# 联机节点图（Ayaya_Miliastra_Editor Graph Code）

> 目标：[AyayaXiaowang/Ayaya_Miliastra_Editor](https://github.com/AyayaXiaowang/Ayaya_Miliastra_Editor)
> 用途：把客户端 Lua 发出的 `ChessSync` 信号转发给房间内所有玩家，实现双人联机。

---

## 0. 先说结论（有一条硬限制）

| 环节 | 官方节点 | Ayaya 节点库 | 能否直接表达 |
|---|---|---|---|
| 客户端 → 服务端 | **监听信号** | ✅ 有 | ✅ 能 |
| 服务端 → 客户端 Lua | **发送客户端脚本信号** | ❌ **没有** | ⚠️ 需手补 1 个节点 |

我核对了 Ayaya 的 `plugins/nodes/server/__init__.pyi`（48,137 字节，**438 个节点定义**），
其中信号相关只有两个：

```python
def 发送信号(game: Any, 信号名: 字符串, **kwargs: Any) -> None: ...
def 监听信号(game: Any, 信号名: 字符串, **kwargs: Any) -> tuple[实体, GUID, 实体]: ...
```

**没有「发送客户端脚本信号」。** 这不是我漏看 —— 我按 `客户端`、`信号`、`广播`
三个关键词全文检索过，都没命中。

### 为什么这个区别是致命的

官方文档《客户端控件和客户端脚本》第五节原文：

> - 客户端脚本通过 `ServerSignal:SendSignal()` 向服务器发送信号
> - 通过服务器节点【**发送客户端脚本信号**】可以向客户端脚本发送信号，
>   客户端脚本通过 `script:RegisterServerSignalHandler(...)` 监听
> - 发送信号延迟：联机情况下，服务器发送信号的延迟最低为 100ms

而【发送信号】节点的官方定义是「向关卡全局发送一个自定义信号」，
接收方是**服务端节点图**（监听信号），**不是客户端 Lua**。

**两者名字极像，选错的表现是：对方永远没反应，且日志里没有任何报错。**

## 1. 我交付的文件

```
nodegraph/
└── assets/资源库/项目存档/黑白棋局/
    ├── 管理配置/信号/
    │   └── signal_chess_sync.py              ← 信号定义（5 个参数）
    └── 节点图/server/实体节点图/chess/
        └── graph_chess_sync_broadcast.py     ← 中继节点图
```

放到 Ayaya 仓库根目录下同名路径即可（`assets/资源库/...` 是它的标准位置）。

### 1.1 信号定义

`signal_chess_sync.py` 声明 `ChessSync` 的 5 个参数，**顺序不能改**：

| 序 | 名称 | 类型 | 走子时的含义 |
|---|---|---|---|
| 1 | `eventType` | 整数 | 0=走子 1=新局 2=认输 3=求和 4=同意和棋 6=身份分配 7=拒绝和棋 |
| 2 | `a` | 整数 | 起点格号（0–63）|
| 3 | `b` | 整数 | 终点格号（0–63）|
| 4 | `c` | 整数 | 升变（0无 1后 2车 3象 4马）|
| 5 | `fen` | 字符串 | 保留，目前恒为空串 |

> 客户端 Lua 按下标读 `params`，顺序错一个就会「走子变成认输」这种诡异现象。

### 1.2 节点图

结构只有一条链路，无任何分支：

```
监听信号(ChessSync)
      │  事件源实体 / 事件源GUID / 信号来源实体 / eventType / a / b / c / fen
      ▼
转发_ChessSync  ← 复合节点，5 个参数原样透传
      ▼
【发送客户端脚本信号】  ← ⚠️ 这一处需要你手补，见下
      信号名 = ChessSync
      目标   = 全部玩家
      eventType / a / b / c / fen ← 接 5 个透传参数
```

我把它做成**复合节点**是有原因的：手补节点时只动这一处，
不会碰到事件节点和信号监听 —— 减少改坏上游的机会。

## 2. 手补那一个节点（约 30 秒）

1. 用 Ayaya 导出 `.gil` 并导入千星沙箱
2. 打开节点图「黑白棋局_联机同步中继」
3. 双击进入复合节点「转发_ChessSync」
4. 选中末尾的【发送信号】节点 → 删除
5. 从节点库拖入【**发送客户端脚本信号**】（在「执行节点 → 信号」分类下）
6. 连线：
   - 信号名 → 选 `ChessSync`
   - 目标 → 选「全部玩家」
   - eventType / a / b / c / fen → 依次接复合节点的 5 个数据入引脚
7. 保存

> **先做前置条件**：千星沙箱 →「服务器信号管理器」→ 添加信号 `ChessSync`，
> 按顺序加 5 个参数（整数×4 + 字符串×1）。
> 不先定义的话，信号名下拉框里选不出来，引脚也不会长出来。

### 3.2 联机实测（判据）

我已经在**千星 UI 模拟器**里跑通了完整链路，用的是等价的模拟器表达
（`serverLogic.rules` 的 `sendClientScriptSignal` kind，和官方节点同名同事义）。
这是当时的实测结果：

```
Player1 走 e2→e4
  → 服务端收到 ChessSync  values=[0, 12, 28, 0, ""]   from=Player1
  → 广播 players=[1, 2]                              delivered=true
  → 切到 Player2 视角：
      白兵在 e4 ✓   走子记录「白 e2→e4」✓
      轮次「轮到黑方走子」✓   双方棋钟各自在走 ✓
```

真机上请按同样判据验收：

1. 两人进同一关卡
2. 白方走 e2→e4
3. **黑方屏幕上应立刻出现白兵在 e4**，走子记录出现「白 e2→e4」
4. 若黑方没反应 → 看客户端日志有没有 `已注册联机信号接收：ChessSync`
   - 有：说明节点图没生效（信号名/参数顺序/目标 三者之一错了）
   - 没有：脚本没挂上或没被调用

> 官方说明：联机信号**最低延迟 100ms**，所以对方响应会比单机慢一点点，属正常。

## 4. 回声过滤为什么不在服务端做

服务端广播会送到房间内**所有人，包括发送者自己**。这是平台行为，不是 bug。

过滤放在**客户端脚本**里（`lua/levelScript.lua` 已实现）：

| 事件 | 过滤方式 |
|---|---|
| 走子 | `GAME.lastSentMove` 匹配 from/to/promo 三项，对上就丢弃 |
| 求和 | `GAME.drawReqSent` 标记 |
| 同意和棋 | `GAME.over` 挡住重复结算 |

不在服务端过滤的原因：需要「信号来源玩家序号」，而信号协议里没有这一项，
为此多加一个参数要改全链路（客户端发送、信号定义、节点图、接收解析），不值当。
