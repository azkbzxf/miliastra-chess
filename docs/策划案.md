## 二、核心亮点

| # | 亮点 | 差异在哪里 | 玩家为什么选它 |
|---|---|---|---|
| 1 | **圆盘棋子，两档可切** | 棋子用「官方实心圆图元染色 + Unicode 棋符」拼成；面板一键在「圆盘+棋符 / 纯棋符」两档间切换，两档都不依赖任何自定义图片 | 打开就是正经棋盘的观感，且零素材配置也能跑 |
| 2 | **规则一条不缺** | 王车易位、吃过路兵、升变、将军、将死、逼和、五十步、三次重复、子力不足全部可玩 | 会下棋的人第一步就会试这些招，少一条立刻判定为残次品 |
| 3 | **每步回补 10 秒** | 15 分钟基础钟 + 每走一步回补 10 秒，快棋手能把时间存起来 | 双人对战最怕一方无限长考，回补让「想久一点」变成可计算的选择 |
| 4 | **选中就把答案摆出来** | 点一枚子，所有能走的格子当场变色，不用背规则 | 新手第一局最大的卡点是「我这匹马能跳哪」，高亮直接消掉这个问题 |
| 5 | **联机不通也能玩** | 主模式联机，备用模式本地同屏，一个按钮切过去 | 联机那半边要另搭服务，搭不出来时这局棋不能变成废案 |

## 三、核心玩法

**玩家一直在重复做的事：** 看清局面 → 点一枚自己的棋子 → 点一个变色的落点 → 把子走过去；每走一步之前都要先算「这样走完，我的王会不会被将军」。

### 3.1 操作方式（键鼠 / 触屏 / 手柄三套写死）

| 操作 | 键鼠 | 触屏 | 手柄 |
|---|---|---|---|
| 选中一枚自己的子 | 鼠标左键点该格（按下与抬起都在同一格才算一次点击） | 单指点按该格 | 十字键把光标框移该格，按确认 |
| 走子 | 左键点高亮格 | 单指点按高亮格 | 光标移到高亮格，按确认 |
| 取消选中 | 右键点任意处，或再点同一枚子 | 再点同一枚子 | 按取消 |
| 点面板按钮 | 左键点按钮 | 单指点按按钮 | 按切焦点，再十字键上下选按钮，按确认；按取消回棋盘 |
| 手柄光标移动 | — | — | 每次跨一格，到棋盘边缘停住不循环；执白初始停在 e2（格号 12），执黑初始停在 e7（格号 52） |

- 手柄的「确认 / 取消 / 切焦点」是本策划给三个功能起的代号，**具体按键枚举名必须从当前接口文档逐字抄**，见第十二节。
- 不支持的输入：拖动棋子、长按、双击加速、双指缩放、滚轮。以上一律按一次普通点击处理；若抬起点不在按下点所在格，整次输入无效。

### 3.2 胜负与重开

| 结果 | 触发 | 结算弹窗 |
|---|---|---|
| 白方胜 | 黑方被将死 / 黑方超时 / 黑方认输 | E-01 将死、E-08 黑方超时、E-10 黑方认输 |
| 黑方胜 | 白方被将死 / 白方超时 / 白方认输 | E-02 将死、E-07 白方超时、E-09 白方认输 |
| 平局 | 逼和 / 五十步 / 三次重复 / 子力不足 / 双方同意和棋 | E-03、E-04、E-05、E-06、E-11 |

- 结算后弹窗只有「再来一局」一个有效入口；棋盘与面板全部点击无效。
- 「再来一局」回到：初始局面、双方棋钟 900 秒、走子记录清空、被吃子记录清空、轮次 = 白方、当前模式不变。不保留上一局任何记录。
- 中途退出不保存局面（本关卡不做存档）。

### 3.3 单局时长

| 段 | 预期时长 | 内容 |
|---|---|---|
| 开局（前 10 步） | 2–4 分 | 双方布子、争中心 |
| 中局（10–40 步） | 8–15 分 | 兑子、易位、攻王 |
| 残局（40 步以后） | 3–8 分 | 少子收束，或进入五十步计数 |
| **整局预期** | **10–20 分钟** | 由双方各 900 秒基础钟决定 |
| **整局上限** | **60 分钟** | 两方棋钟各自封顶 1800 秒 |

### 3.4 难度变化

- **不做难度档位**。难度 100% 来自对手水平与时间压力，不来自系统。
- 唯一的难度曲线是棋钟：开局时间宽裕；走到 20 步以后双方剩余时间同时见底，每步 10 秒的回补开始不够用，逼着玩家在残局提速。

## 四、规则清单

类别标记：**【体验假设】** 只能靠试玩判断；**【可测试规则】** 可写成确定性验收用例；**【未知事实】** 依赖平台能力，缺依据不猜。
每条格式统一为「在什么状态下 → 玩家做什么 → 期望看到什么」。

### 4.1 选子与走子

| 编号 | 类别 | 状态 → 操作 → 期望 | 边界与异常 |
|---|---|---|---|
| R-01 | 可测试规则 | 轮到自己、该格有自己的子 → 点该格 → 该格底色变选中高亮 (250,198,74)，该子全部合法落点格底色变落点高亮 (108,186,130) | 点对方子不选中；点空格不选中；连点同一格 = 取消 |
| R-02 | 可测试规则 | 已选中 A 格 → 再点 A 格 → 所有高亮恢复原色，选中态清空 | 两帧内两次点击等价于选中后取消，不产生走子 |
| R-03 | 可测试规则 | 已选中 A，B 既不是合法落点也不是自己的子 → 点 B → 高亮全清，提示条显示「这一步走不了」，棋钟与局面不变 | 点对方子（且不是合法落点）只取消选中，不触发吃子 |
| R-04 | 可测试规则 | 选中子 → 先按棋子走法生成伪合法落点，再逐个试走，剔除走完自己被将军的落点 → 高亮里只剩最终合法落点 | 王车易位在被将军、经过格被攻击、落点格被攻击时整条剔除 |
| R-05 | 可测试规则 | 已选中 A，B 是合法落点 → 点 B → 子移到 B；B 有对方子则该子消失并记入被吃子记录；轮次切给对方；本方棋钟 +10 秒 | 兵走到对方底线先弹升变（R-08），升变完成前局面不推进 |
| R-06 | 可测试规则 | 王与对应车都未动过、中间无子、王不在被将军、王经过格与落点格均不被攻击 → 点王后 g1/g8（短易位）或 c1/c8（长易位）格变高亮 → 点该格 → 王移两格、车跳到王内侧 | 任一条件不满足该格不出现在高亮里；易位后王与车的易位权各自清零，且不可恢复 |
| R-07 | 可测试规则 | 对方兵上一步从起始横排直走两格、落到与我方兵相邻列 → 我方兵可走到该兵身后的空格，同时该对方兵消失 | 该机会只在紧接的下一步有效，再下一步自动失效 |
| R-08 | 可测试规则 | 兵走到对方底线 → 弹升变弹窗（后/车/象/马 四选一）→ 点选 → 该格显示对应棋子图标（后/车/象/马），局面推进 | 弹窗期间双方棋钟冻结；点遮罩或手柄按取消 = 取消本次走子，子回原位，轮次不变，棋钟解冻 |
| R-09 | 可测试规则 | 选中自己的子 → 高亮格数量 = 该子最终合法落点数，不多不少 | 同一目标格只高亮一次；易位只高亮王落点格，不高亮车的格子 |

### 4.2 将军与终局

| 编号 | 类别 | 状态 → 操作 → 期望 | 边界与异常 |
|---|---|---|---|
| R-10 | 可测试规则 | 一方走子后对方王处于被攻击 → 提示条显示「将军！」/「你的王被将军了」，对方王所在格底色变将军警示 (214,70,66) | 将军只提示不结算；王永远不会被吃（走法里已剔除） |
| R-11 | 可测试规则 | 对方被将军且试遍全部子均无合法走子 → 立即结算，弹窗「白方将死黑方，白方胜」或「黑方将死白方，黑方胜」，双方棋钟停止 | 结算那一帧之后的点击全部无效 |
| R-12 | 可测试规则 | 对方未被将军但无任何合法走子 → 平局结算，弹窗「无子可动，本局和棋」 | 与 R-11 同一判定入口，先判是否被将军，再判合法走子数 |
| R-13 | 可测试规则 | 连续 50 步（100 个半步）内无吃子、无兵移动 → 平局，弹窗「五十步无进展，本局和棋」 | 任一次吃子或兵移动把计数清零；计数只在走子成功时更新 |
| R-14 | 可测试规则 | 同一局面（子力位置 + 轮到谁 + 双方易位权 + 过路兵格）第 3 次出现 → 平局，弹窗「局面重复三次，本局和棋」 | 第 3 次出现的那一帧立即判，不等下一步；局面比对用完整键，不抽样 |
| R-15 | 可测试规则 | 双方只剩 王 vs 王 / 王+单马 vs 王 / 王+单象 vs 王 / 同色格象各一 → 平局，弹窗「子力不足，本局和棋」 | 王+两马 vs 王、王+象+马 vs 王 不判和（保守处理，仍可继续下） |

## 五、数值

### 5.1 棋盘与子力

| 项 | 值 |
|---|---|
| 棋盘 | 8 × 8 = 64 格 |
| 格号 | 0–63；格号 = 行 × 8 + 列 |
| 行与列定义 | 行 0 = 第 1 横排（画面最下一排，白方底线）；列 0 = a 列。a1 = 0，h1 = 7，a8 = 56，h8 = 63 |
| 每方子力 | 1 王 K、1 后 Q、2 车 R、2 象 B、2 马 N、8 兵 P（共 16） |
| 全场子力 | 32 |
| 单方子力上限 | 16（升变只换棋子类型，不增加子数） |

### 5.2 棋钟

| 项 | 值 |
|---|---|
| 每方初始 | 900 秒（显示 15:00） |
| 每走完一步该方加 | 10 秒 |
| 每方上限 | 1800 秒（显示 30:00），到顶后不再加 |
| 计时方式 | 逐帧累加：只有轮到的一方的剩余时间在减少；不读现实时间、不用系统时钟差 |
| 显示格式 | MM:SS，秒数向下取整 |
| 判负 | 剩余时间减到 0 的那一帧，该方判负 |

**算术自查（必须自洽）：**

- 公式：`剩余 = 900 − 本方累计消耗 + 10 × 本方已完成步数`，结果封顶 1800。
- **40 步示例（派单要求）**：白方走完 40 步，累计消耗 800 秒 → `900 − 800 + 400 = 500 秒`（显示 08:20）。
- **60 步示例**：全场 60 步 = 白方 30 步 + 黑方 30 步。
  - 白方每步平均 12 秒，累计消耗 360 秒 → `900 − 360 + 300 = 840 秒`（14:00）。
  - 黑方每步平均 9 秒，累计消耗 270 秒 → `900 − 270 + 300 = 930 秒`（15:30）。
  - 实际对局时长 `360 + 270 = 630 秒 = 10:30`，两方剩余都远高于 0，未触发封顶。
- **极速示例**：一方每步只用 3 秒，每步净赚 7 秒；走 30 步后 `900 − 90 + 300 = 1110 秒`（18:30），未到 1800 上限。
- **上限校验**：单方要 90 步才把 1800 用满（`900 + 10 × 90 = 1800`），与「整局上限 60 分钟」（`1800 + 1800 = 3600 秒`）一致。

## 十、界面与场景

### 10.1 坐标与布局约定

设计基准 **1600 × 900**。所有元素锚点左下角 (0,0)、中心点 (0,0)，位置以画布左下为原点，y 向上为正。相对值一律给百分比，同时给 1600×900 下的绝对像素。

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│              ┌──────────────┐        ┌────────────┐      │
│              │   8×8 棋盘    │        │  侧面板    │      │
│              │  边长=画布高78%│        │ 宽=画布宽22%│     │
│              │  水平垂直居中  │        │ 靠右垂直居中│     │
│              └──────────────┘        └────────────┘      │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**唯一换算处（代码中只允许在这一处出现该换算）：**

```
boardSide   = 0.78 * canvasH          -- 棋盘边长
cell        = boardSide / 8           -- 格宽 = 格高
boardLeft   = (canvasW - boardSide) / 2   -- 水平居中
boardBottom = (canvasH - boardSide) / 2   -- 垂直居中
panelW      = 0.22 * canvasW
panelH      = boardSide
panelLeft   = canvasW - panelW        -- 靠右
panelBottom = (canvasH - panelH) / 2  -- 垂直居中，与棋盘同高同底
```

1600×900 代入：boardSide = 702，cell = 87.75，boardLeft = 449，boardBottom = 99，panelW = 352，panelLeft = 1248，panelH = 702，panelBottom = 99。棋盘右边缘 1151 与面板左边缘 1248 之间留 97px 空隙。

**窄屏降级（唯一例外）**：若「整块画布水平居中后的棋盘右缘」会压到面板左缘，即 `(canvasW + boardSide) / 2 > canvasW − panelW`，棋盘改为在「面板左侧区域」内水平居中：`boardLeft = (panelLeft − boardSide) / 2`。目前只有手机 4:3 1280×960 触发（`(1280 + 748.8) / 2 = 1014.4 > 1280 − 281.6 = 998.4`），该分辨率下 boardLeft = 124.8，棋盘右缘 873.6，与面板左缘留 124.8。其余七个比例均不触发。

## 十五、引导与教学

### 15.1 前 30 秒怎么让玩家明白「点棋子 → 点落点」

| 时间 | 做法 | 玩家看到 |
|---|---|---|
| 0–3 秒 | 棋盘上方提示条 + e2 格染建议色 | H-01「点一枚自己的棋子」，e2 一格淡绿 |
| 3–8 秒 | 玩家点任意自己的子后，立即高亮该子与全部落点 | H-02「绿格是能走的位置」 |
| 8–15 秒 | 玩家点第一个绿格，棋子走过去，上一步痕迹留在起点与终点 | H-03「点绿格，棋子就过去」 |
| 15–22 秒 | 玩家第二次选子时，提示补一条取消方式 | H-04「再点同一枚，就取消」 |
| 22–30 秒 | 全部教学提示收起，只保留轮次状态；此后按正常节奏走 | S-01～S-06 |

- 教学不锁输入、不弹模态框、不暂停棋钟。
- 首次选中后 7 秒仍未点落点，H-04 覆盖 H-03，不叠加显示。

### 15.2 前 3 分钟：让玩家尝到核心乐趣

- 落点高亮全程开启，玩家不用背走法就能把子动起来。
- 上一步痕迹让玩家看懂对方刚动了哪枚子、从哪到哪。
- 被吃子记录与走子记录提供「刚才发生了什么」的可追溯性。
- 3 分钟内至少能走完 8–10 步，遇到第一次将军的概率高，H-07 / H-08 会即时解释。

### 15.3 3 分钟以后：进阶机制按需出现

不做主动教学，只在玩家第一次遇到时给一行提示：

| 机制 | 首次触发提示（逐字） |
|---|---|
| 王车易位可用 | 高亮直接出现在 g1 或 c1 格，不额外提示 |
| 吃过路兵可用 | 高亮直接出现在过路兵身后空格，不额外提示 |
| 升变 | H-11「兵到底了，选一个子」+ 四选一弹窗 |
| 求和 | C-04「对方想和棋，同意吗」 |
| 超时 | 结算弹窗 E-07 / E-08 |

### 15.4 可能卡住的地方与对策

| 卡点 | 对策 | 玩家看到的原文 |
|---|---|---|
| 不知道要点两次 | 开局提示直接写两步动作 | 点一枚自己的棋子 / 点绿格，棋子就过去 |
| 不知道哪些格能走 | 全部合法落点绿色高亮 | 绿格是能走的位置 |
| 不知道自己被将军 | 王所在格变红 + 提示条 | 你的王被将军了 |
| 升变不知道怎么选 | 四选一弹窗，选项写中文名 | 兵到底了，选一个子 / 后 车 象 马 |
| 分不清轮到谁 | 面板轮次区一行大字 | 你是白方 · 轮到你 |
| 不知道对方求和怎么回应 | 求和弹窗两个按钮 | 同意和棋 / 拒绝求和 |
| 联机等不到人 | 提示条常驻 + 可切本地 | 等待另一位玩家加入 / 没人接上，先和身边的人下 |

## 附录 A　技术倾向（含联机同步）

### A.1 实现风格

- 单文件 Lua，全部界面元素在启动时一次性建好（64 格底 + 64 棋子 + 27 落点高亮 + 1 选中 + 2 痕迹 + 1 警示 + 面板与弹窗），运行期只改 `text` 与 `bgColor`，不动态增删控件。
- 状态机集中在「输入与交互」一段：`空闲 → 已选中 → 走子提交 → 终局`。任何一帧只允许一个状态。
- 规则内核与界面完全解耦：走法生成只吃「局面 + 格号」，不读控件；界面只吃「高亮列表 + 文字」。
- 棋钟用逐帧累加，不读现实时间，保证沙箱与真机判定一致。

### A.2 联机同步（客户端一半）

客户端发 `ChessSync` 信号，参数顺序固定为 5 个：

```
AddInt(eventType)      -- 事件类型
AddInt(a)              -- 参数一
AddInt(b)              -- 参数二
AddInt(c)              -- 参数三
AddString(fen)         -- 局面串（走子事件必填，其余事件传空串）
```

| eventType | 含义 | a | b | c | fen |
|---|---|---|---|---|---|
| 0 | 走子 | 起点格号 0–63 | 终点格号 0–63 | 升变：0 = 非升变；1 = 后 Q；2 = 车 R；3 = 象 B；4 = 马 N | 走子后的完整局面 |
| 1 | 新局 | 0 | 0 | 0 | 初始局面 |
| 2 | 认输 | 认输方 0 = 白 / 1 = 黑 | 0 | 0 | 空串 |
| 3 | 求和 | 发起方 0 = 白 / 1 = 黑 | 0 | 0 | 空串 |
| 4 | 同意和棋 | 同意方 0 = 白 / 1 = 黑 | 0 | 0 | 空串 |
| 5 | 请求加入 | 0 | 0 | 0 | 空串 |
| 6 | 身份分配 | 0 = 你是白方 / 1 = 你是黑方 | 0 | 0 | 空串 |

- **身份流程**：客户端启动时发 `ChessSync(5,0,0,0,"")`；服务端按收到顺序回广播 `eventType=6`，第一个拿到 a=0（白方），第二个拿到 a=1（黑方）。
- **服务端退化**：服务端若做不了身份分配，则退化为「先进入者执白、后进入者执黑」，界面照样显示「你是白方 / 你是黑方」，不提示任何技术原因。
- **服务端节点图职责（只有一件事）**：收到名为 `ChessSync` 的信号 → 把 5 个参数原样广播给全房间，广播名同样叫 `ChessSync`。不做校验、不做落库、不做排序。
- **本端防回声**：收到广播先比对 a/b/c 与 fen，若与本端刚发出的一致则丢弃，避免自己走子被二次应用。
- **局面重建**：一律以广播里的 fen 为准覆盖本端局面，不做增量推算，避免两端分叉。
- **失败降级**：任一环节不可用（信号发不出、收不到、身份超时 10 秒）→ 提示条「没人接上，先和身边的人下」，自动进入本地同屏模式，按钮文字变「切换联机对战」。

### A.3 为什么必须有本地同屏备用

服务端节点图不在本项目的接口文档里，代码只能交付客户端这一半。若用户暂时不搭服务端，主模式（联机）将无法完成一局；本地同屏是同一套规则内核、同一套界面，只把「轮到谁」从网络身份换成「按轮次交替」，因此能在沙箱与真机上完整验证全部规则、棋钟与结算。**这是备用模式存在的唯一理由**。

## 附录 C　设计说明

- **为什么全部用色块与文字自绘**：平台图片控件只能引用官方白名单素材（无上传入口），且已全量核查 1517 个素材无国际象棋棋子。用文本框底色当色块、Unicode 棋符当棋子，零依赖、必定能显示，任何分辨率都不会缺图；圆盘档额外用官方「实心圆」图元 `100002` 染色，仍不依赖任何自定义图片。
- **为什么棋盘居中、面板靠右**：棋盘是视觉重心，居中符合直觉；面板靠右留出空隙，保证任何比例下二者不重叠（唯一的窄屏例外已在 10.1 写死）。
- **为什么棋钟用逐帧累加**：不依赖现实时间，沙箱里可以用固定帧步进复现超时，判定可测试。
- **为什么不做悔棋**：联机时对方已经看到走法，悔棋会泄露信息；同屏时容易误触。不做比做错好。
