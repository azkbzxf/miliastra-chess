# v3 用例 · 无待机室快速开局 + 随机黑白与视角匹配

> 需求来源：用户 2026-11 真机反馈（两条）。
> 用例先于实现写（步骤 2），每条都要有「可观察结果」，不写「函数被调用」这种实现断言。
> runtime 标记：`simulator` = 千星 UI 模拟器；`device` = 真机（本轮由用户验）；`static` = node 门禁。

## 一、需求 → 用例追踪

| 需求 | 原文 | 用例 |
|---|---|---|
| R1 | 双人进入后不应有待机室 | M1、M2、M12 |
| R2 | 双方玩家选择时间后自动将两名玩家拉入对战，时间按玩家所选 | M3、M4 |
| R3 | 界面中应有提示对方所选的什么时间 | M5 |
| R4 | 若两人所选时间不同则给 5 秒等待 | M6 |
| R5 | 若双方不愿意更改则在 2 种情况中随机选 | M7 |
| R6 | 双人进入对战后随机分配黑白 | M8 |
| R7 | 视角匹配（黑方看黑棋在下、白方看白棋在下） | M9 |
| R8 | 棋子保持正立 | M10 |
| R9 | 单人/同屏路径不被破坏 | M11、M12 |

## 二、用例（操作 → 期望可观察结果）

| # | 操作 | 期望 |
|---|---|---|
| **M1** | 玩家 A 进入关卡 → 停在初始界面 | 画面上**没有**「联机·待机室」可进入的整层界面；初始界面直接可选时间档（不改 screen 也能开局） |
| **M2** | 点第三个入口「双人·联机对战」 | 不进入待机室整层；仅在初始界面上显示「已把你的时间档告诉对手」类提示 |
| **M3** | A 选「快棋」，B（另一客户端）也选「快棋」 | 两端**都自动**进入棋盘（无需再点准备/开始），棋钟 = 15:10 档（900+10） |
| **M4** | A 选「闪电战」、B 选「快棋」且 5 秒内都不改 | 5 秒后两端**采用同一个**档位（要么都是闪电战、要么都是快棋），棋钟按该档初始化；两端档位必须相同 |
| **M5** | A 选好后，B 还没选 | A 的初始界面出现「对手选了「X」」/「等对手选择」文案；B 看到「你还没选 · 对手选了「X」」 |
| **M6** | A、B 档位不同 → 第 3 秒 B 改成与 A 相同 | 立即开局（不等满 5 秒），档位 = 双方相同的那一档；改选窗口内界面有剩余秒数提示 |
| **M7** | 档位不同且 5 秒内都不改 | 随机采用其中一个：两端结果一致；可重复多局观察到两种结果都会出现（不是固定偏向） |
| **M8** | 进入对局 | 两端 one 白 one 黑；多次重开两色都会出现（随机，不固定） |
| **M9** | 黑方客户端看棋盘 | 黑棋在屏幕**下方**两行、白棋在上方；左侧行号自下而上是 8→1，底部列字母自左而右 h→a |
| **M10** | 黑方客户端看任意一枚棋子 | 棋子**正立**（不是倒着的剪影），王冠/马头朝上 |
| **M11** | 点「单人·双人同屏」 | 棋盘方向与 v2.0 一致（白棋在下、a1 在左下），不做翻转；可正常走子 |
| **M12** | 单人（房间内没有第二个客户端） | 不会卡死；初始界面可用单人入口直接开局；选时间档不会把单人玩家留在「等待」里无法退出 |
| **M13** | 黑方轮到时点黑兵 → 点目标格 | 高亮落在**屏幕上被点的那一格**（命中换算与翻转一致），棋真的走成 |
| **M14** | 白色走完 → 黑方看走子记录 | 记录文字仍按坐标书写（`白 e2→e4`），不因翻转而改变 |

## 四、模拟器执行方案（runtime=simulator）

模拟器只有一份客户端脚本、但可开 `playerCount: 2`；同时 `qxqy_studio_play serverSend` 可以伪造「对端包」，
因此每条协商分支都能被单独、可重复地触发（比等服务端转发更可控）：

1. `qxqy_studio_load workspace/chess/chess.save.json` → `play start {playerCount:1}`（单人视角足够）
2. **M1/M2/M5**：初始界面截图 + `get` 日志；`serverSend ChessSync [8,1,2,0,"P999999999999"]` 模拟对端选闪电战 → 截图应出现「对手选了闪电战」
3. **M6**：再发 `[8,1,3,0,...]`（= 与我相同的快棋档）→ 立即开局，日志出现「联机开局：档位=3」
4. **M4/M5/M7**：新开一局（回主菜单）→ 我选 3（快棋）→ 发对端 `[8,1,2,0,"P999999999999"]` → 界面出现 5 秒倒计时 → `step` 推进 5 秒 → 两端采用同一档（本端日志给出档位与「我执黑/白」）
5. **M8/M9/M10/M13**：伪造的对端随机数取极大值（`P9…`）⇒ 本端必为黑方 ⇒ 截图必须黑棋在下、棋子正立、坐标 8→1 / h→a；再 `serverSend ChessSync [0,12,28,0,""]`（白 c2→c4）把轮次交给黑方 → 点底部的黑兵和它的目标格，确认高亮与落子都在被点的格子上
6. **M11/M12**：回主菜单点「单人·双人同屏」→ 截图确认未翻转（白在下）、走子正常
7. 每条结果写进 `records/playtest-v3.md`，并区分 `runtime=simulator`；真机结论留空待用户验

> 说明：模拟器里两个客户端**可能**在同一帧被点击（帧节奏完全相同），此时本端随机数会相同，
> 协商标识会撞车（见实现注释的「已知边界」）。所以第 5 步用 `serverSend` 指定对端随机数，
> 让「随机数比较」这条判据**可确定地**被验证，而不是靠运气。
