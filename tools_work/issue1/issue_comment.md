## 逐条对照

### 1. 走棋特效错位严重 ✅
**根因**：落点高亮用的是**图片控件**，而图片控件 `pivot=0.5`（按中心定位），
代码却一直喂 `LAYOUT.square_pos` 返回的**格子左下角**坐标 ——
所以空格绿点偏左下约 0.35 格，可吃子红罩偏左下约 0.5 格，越靠棋盘边越明显。

**修法**：改用格中心 `tx + L.cell*0.5`，并同步 `ANIM.hlBase`（呼吸动画的基准点）。

### 2. 多走几步后棋子图元开始错位 ✅
**根因**：`image_apply` 只在 `rot ~= 0` 时才写 `SetLocalRotation`。
棋子槽位是**回收复用**的 —— 白车（-1°）占过的槽位被白兵（0°）接手时，
因为「0 度不写」，兵就继承了车的角度。所以**开局全对、走几步才乱**（初次布子时槽位干净）。

**修法**：无条件写（`local r = rot or 0`），靠 `IMG_STATE` 的**值比较**跳过重复写
（而不是靠「值是不是 0」判断）。

**验证**：走完吃子链后 `get{inspect:true}` 扫盘，628 个在显图元的旋转值
**全部落在 `PIECE_ART` 的 51 个合法角度内，零个残留**。

### 3. 优化右侧信息栏 ✅
**根因**：面板坐标散落在 `build_panel` 几十处手算表达式里，改一处不影响别处 ——
于是「失子行」与「走子记录区」在 1600×900 下纵向重叠 0.013~0.020 个面板高度，
1280×720 下压得更明显，屏幕上是失子字母直接压在走子记录文字上。

**修法**：
- 抽出 `CONFIG.PANEL_LAYOUT` 作为面板竖向排布的**唯一事实来源**（11 个槽位），
  `build_panel` 全部改为 `band("NAME")` 读表
- 棋钟从「上下两行」改成「**并排一行**」（各半宽），这就是腾出空间的关键一步；
  代价是字号 36 → 28（否则「白 15:00」放不进半宽会被截断）
- 失子行补前缀「失子 」（原来只有 `P P N` 看不出是谁的子），空列表显示「无」
- 走子记录空态显示「还没有走子」
- 按钮高度加 `max(44, ...)` 兜底（触摸设备上小于 44px 点不中）

现在 11 项两两不相交，且由两道门禁守护（`CHECK-6` + `consistency_check` 逐项比对）。

### 4. 删除纯字体棋子画法，README 换模拟器真实截图 ✅
- Demo 删掉 `GLYPH` 表、`pieceGlyph()`、`pieceStyle`、`?style=` 参数、
  圆盘 CSS 与槽位三件套
- 改为与 Lua **同一份 `PIECE_ART`**（74 条形状，逐字段相同）、
  **同一套五层顺序**（描边 → 填充 → 镂空描边 → 镂空填充 → 细节线）
- 被吃子记录也顺带从棋符改成字母 `P/N/B/R/Q/K`（与 Lua 同口径）
- README 主图换成模拟器实拍（`pc-16-9` + `mobile-16-9`），
  删掉 `screenshot-pieces-glyph.png`

### 5. 删除棋子底部阴影，并让棋子在格中平衡 ✅
- **删投影层**：棋盘浅木格上的半透明椭圆其实更像脏斑，而且投影只能整体压在底座下方，
  与「视觉居中」直接冲突。六层渲染 → 五层，控件 **1399 → 1367**（每枚少 1 个 × 32 槽）。
- **视觉居中**：六种棋子的形状并集竖向中心并不都在 0.5（实测 0.463~0.510），
  按旋转后 AABB 并集算出一个**全局**位移 `+0.0080920453` 统一基线。
- 必须是全局单一位移 —— 逐枚各自居中会把兵拉成和王一样高（实测高度比 0.909），
  六种棋子就分不出大小了。
- 实测 32 枚棋子的内容包围盒与格心偏差 **≤ 2.9px**（81px 棋子方框）。

### 6. 保证功能不变的前提下优化性能 ✅
v1.10 已经做了「动画期只重绘脏槽位」，但**每个槽位内部**仍然每次全写一遍，
其中图元 / 颜色 / 旋转三项在动画期间**根本不变**（动画只改尺寸与位置）。这一轮再加：

- `IMG_STATE`：弱键表记录每个图片控件当前的 asset/color/rot，命中就跳过平台调用
- `VIS_STATE`：记录每个控件当前 active，跳过重复的 `SetActive` + `SetVisible` 成对写
- 文本写缓存：棋钟 / 轮次 / 失子 / 走子记录都只在文本真的变化时才写

> 缓存**必须放脚本侧弱键表**，不能挂在控件对象上 —— 平台控件可能是带严格元表的 userdata，
> `ctrl.__imgAsset = x` 会抛 "no such field"。

并新增**可复测**的计量口（不是只写在文档里的数字）：
`GetRepaintStats()` 多返回 `ctrlWrites` / `ctrlWritesSkipped`，
`ResetRepaintStats()` → 走一步 → 读两个数就能自己验证省了多少写。
`DumpRepaintStats(tag)` 会往日志打一条 `REPAINT[...]`。
