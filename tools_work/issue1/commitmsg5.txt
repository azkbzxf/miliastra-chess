feat: 生成可导入游戏的 .gil 关卡存档（含脚本源码）

用户要求「导入存档只接受 gil 后缀」。此前交付的是 .gia 资产包，入口不同，
本次真正生成 .gil 关卡存档。

## 为什么必须做 .gil
游戏端「导入存档」对话框的文件类型过滤器写死为 `gil Files`。实测把 .gia
填进该对话框后，游戏强行追加后缀生成 `xxx.gia.gil`，且为 0 字节空壳 ——
证明 .gia 在这条路径上被硬性拒绝，不是文件损坏。

## 逆向出的 .gil 格式（无官方文档）
容器：`[总长][版本=1][魔数=0x326][分片数][分片长][protobuf]`
- 魔数 0x326 与 .gia 相同 → 两者同源
- 分片0 为 protobuf，46 个顶层字段

关键字段：
- field 9  = UI 控件模板（field501 头 + field502 各模板）
- field 43 = 编辑器版本号
- field 50 = Lua 脚本列表：
  `{1:{1:id, 2:name, 3:file, 5:source}}`
- **源码是明文 UTF-8**，这是能做到生成的关键

## 实现
tools_work/gil/build.py：
1. 解析容器，先做「原样重建 == 原 body」往返测试（必须 True 才继续）
2. 从 field 9 读出 4 个模板真实索引
3. 把脚本里 4 个占位符 0 替换成真实索引
4. 构造 Script 消息写入 field 50，重算所有 varint 与容器头部

用户存档中的实际索引：
  CONTAINER_NODE_INDEX = 1073741906
  PREFAB_IMAGE         = 1073741867
  PREFAB_TEXT_BOX      = 1073741868
  PREFAB_CURSOR_AREA   = 1073741869

## 校验（全部通过）
- 原样重建逐字节相同
- total == 文件-4；frag0len == body 长度
- 除 field 50 外 45 个字段逐字节未变（差异 0）
- field 50 可解析回 Script 结构，源码 228,066 字节 / 5201 行
- 脚本往返：除 4 行索引外 5197/5201 行逐行相同（无换行符损坏）

## 顺带清理死代码
发现脚本里仍留着 v1.5 的 12 份拟合数据加载器（load_piece_fit /
PIECE_DATA_TAG / PIECE_FIT / FIT_ALPHA_MIN / fit_normalize，L914-L1103），
v1.7 起已被 PIECE_ART 取代，从不调用。其中含 `pcall(require, ...)`，
虽然被 pcall 包着不会崩，但在没有 require 的真机环境里是隐患。
逐一核对 6 个符号的外部引用均为 0 后整段删除（5391 → 5201 行）。
