fix: 修 4:3 画布字号裁切 bug（fontScale 只看高度），补齐全五档画布实测

补跑剩余三档画布（pc-21-9 / mobile-19.5-9 / mobile-4-3）时发现一个真 bug，
issue #1 第 3 条「优化右侧信息栏」的延伸问题。

## 症状
手机 4:3（1280×960）下面板按钮「切换本地同屏」被截成「切换本地」，
两个棋钟也挤在一起。

## 根因
fontScale 只按 canvasH / 900 算，但**面板宽度是按 canvasW 的比例算的**：

  pc-16-9      1600x900  字 1.000 / 容器 1.000  -> 正常
  mobile-16-9  1280x720  字 0.800 / 容器 0.800  -> 正常
  mobile-4-3   1280x960  字 1.067 / 容器 0.800  -> 相对溢出 1.33 倍，裁切

4:3 画布「更高但更窄」：字号跟着变高变大，容器却跟着变窄变小，两头反向。

## 修法
fontScale = min(canvasW / BASE_CANVAS_W, canvasH / BASE_CANVAS_H)
取两个方向的较小者，保证文字永远不会比它所在的容器长得快。

选 min 而不是别的公式的理由：它让已实测的四档画布数值**逐位不变**
（1600x900 / 2100x900 / 1280x720 / 1560x720 都是宽高同比或宽度更紧），
只有原本出错的 4:3 从 1.067 修正为 0.800。换任何别的公式都会牵动已验证档位。

Demo 侧同式同步修改（const fontScale = Math.min(...)），两份 SHA256 一致。

## 门禁
新增 CHECK-8：断言 fontScale 表达式同时含 canvasW / canvasH 且用了 math.min，
并把五档画布的新旧 fontScale 打进输出（哪一档被修正一眼可见）。

这条 bug 在 1600x900 与 1280x720 上完全看不出来，只有 4:3 这种
「更高但更窄」的画布才暴露 —— 靠人眼验会一直漏，所以必须做成静态门禁。
